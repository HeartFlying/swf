# Agent+Skill 框架在 Trae IDE 中的配置与执行指南

## 快速开始（5 分钟上手）

### 第一步：打开项目

1. **启动 Trae IDE**
2. **打开项目文件夹**：`e:\code\LLM\workspace\swf`

### 第二步：理解架构

这是一个**基于 Prompt 的 Agent+Skill 框架**，通过 Trae IDE 的 AI 能力执行：

```
用户输入需求 → Coordinator Agent → 调度其他 Agent → 执行 Skill → 输出结果
```

**核心组件**：
- **4 个 Agent**：coordinator.md（主协调）、validator.md（校验）、user-interaction.md（交互）、executor.md（执行）
- **13 个 Skill**：S0-S4 五个阶段，覆盖需求分析全流程
- **1 个工作流程**：WORKFLOW.md（定义协作规则）
- **中心化信息库**：database/目录存储所有状态和产物

### 第三步：首次执行测试

#### 方式 1：直接输入需求（推荐新手）

1. **在 Trae IDE 中打开对话框**
2. **输入以下指令**：

```
请作为 Coordinator Agent，执行以下需求：

需求描述：我想做一个刷题 APP。

请按照 WORKFLOW.md 定义的流程，从 Skill0 开始执行，生成 Plan 并逐步执行各阶段 Skill。
```

3. **等待 AI 响应**：AI 会自动：
   - 执行 Skill0 制定 Plan
   - 评估信息完整度（应<90 分，触发常规模式）
   - 逐步执行 S1→S2→S3→S4 各阶段
   - 在 3 个交互节点暂停等待您的确认

#### 方式 2：使用示例需求

1. **查看示例需求**：
   - [examples/sample-requirement-vague.md](examples/sample-requirement-vague.md) - 模糊需求（常规模式）
   - [examples/sample-requirement-complete.md](examples/sample-requirement-complete.md) - 完整需求（轻量化模式）

2. **复制示例需求内容**，在 Trae IDE 中输入：

```
请作为 Coordinator Agent，执行以下需求：

[粘贴示例需求内容]

请按照 WORKFLOW.md 定义的流程执行。
```

### 第四步：查看执行结果

执行完成后，查看产物文件：

```
database/plans/{PlanID}/
├── plan.json              # Plan 配置
├── status.json            # 执行状态
├── resume.json            # 断点续跑配置
├── s1-summary.md          # S1 阶段汇总
├── s2-summary.md          # S2 阶段汇总
├── s3-summary.md          # S3 阶段汇总
└── s4-summary.md          # S4 阶段汇总（最终产物）
```

### 3. 执行模式说明

系统支持**两种执行模式**，自动切换：

#### 常规模式（Normal Mode）

- **触发条件**：需求信息完整度评分 < 90 分
- **执行流程**：完整执行所有 13 个 Skill（S0→S1→S2→S3→S4）
- **用户交互**：3 个交互节点（信息补全、产物确认、风险决策）
- **适用场景**：模糊需求、信息不完整的需求

**示例**：
```
输入："我想做一个刷题 APP。"
评分：35 分
模式：常规模式
执行 Skill：全部 13 个
```

#### 轻量化模式（Lightweight Mode）

- **触发条件**：需求信息完整度评分 ≥ 90 分
- **执行流程**：跳过 S2 阶段（Skill9、Skill10），共 11 个 Skill
- **用户交互**：无交互（全程自动执行）
- **默认值填充**：
  - 竞品分析：默认"市场上已有类似产品，但差异化空间较大"
  - 市场痛点验证：默认"目标用户群体明确，痛点真实存在"
- **适用场景**：详细完整的需求文档

**示例**：
```
输入：完整的需求文档（包含产品目标、目标受众、核心场景、功能需求等）
评分：95 分
模式：轻量化模式
执行 Skill：跳过 Skill9、Skill10
执行时间：约为常规模式的 60%
```

### 4. 状态管理

系统通过**文件系统**实现状态持久化：

#### 核心状态文件

| 文件 | 路径 | 作用 |
|------|------|------|
| **status.json** | `database/plans/{PlanID}/status.json` | 当前执行状态 |
| **resume.json** | `database/plans/{PlanID}/resume.json` | 断点续跑配置 |
| **plan.json** | `database/plans/{PlanID}/plan.json` | Plan 配置信息 |

#### 状态追踪

- **自动保存**：每个 Skill 执行完成后自动更新状态
- **断点续跑**：支持中断后从断点位置恢复
- **历史追溯**：所有产物永久保存，可追溯历史版本

### 5. 用户交互节点

系统在以下 3 个节点会暂停并等待用户输入：

#### 节点 1：信息补全（S1 阶段完成后）

**触发时机**：S1 阶段（需求边界与原始采集）完成后

**交互内容**：
```
已完成需求边界界定和原始采集，请确认或补充：

1. 需求边界是否清晰？
2. 是否有需要补充的目标用户？
3. 是否有需要补充的使用场景？

请输入：
- 选择：1（确认）或 2（补充/修改）
- 补充内容：（如果选择 2）
```

**用户输入格式**：
- **确认**：输入 `1` 或 `确认`
- **补充**：输入 `2` + 补充内容
- **修改**：输入 `2` + 修改内容

#### 节点 2：产物确认（S3 阶段完成后）

**触发时机**：S3 阶段（技术可行性与选型）完成后

**交互内容**：
```
已完成技术可行性评估和选型，请确认：

1. 技术路线是否合理？
2. 技术选型是否符合预期？
3. 是否继续执行 S4 阶段？

请输入：
- 选择：1（确认）或 2（调整）
- 调整建议：（如果选择 2）
```

#### 节点 3：风险决策（高风险需求）

**触发时机**：识别到高风险需求时

**交互内容**：
```
识别到以下高风险项：

1. [风险描述]
   - 影响：[影响说明]
   - 建议：[应对建议]

请选择：
1. 接受风险，继续执行
2. 调整需求，规避风险
3. 暂停任务，进一步讨论

请输入选择：
```

## 故障排查

### 问题 1：AI 不执行 Skill

**现象**：AI 只聊天，不执行实际任务

**原因**：没有明确指定执行流程

**解决方案**：
```
请明确指令：
"请作为 Coordinator Agent，按照 WORKFLOW.md 定义的流程，
从 Skill0 开始执行，逐步完成各阶段 Skill。"
```

### 问题 2：状态文件未更新

**现象**：执行完成后找不到产物文件

**原因**：AI 没有正确保存产物

**解决方案**：
1. 检查 AI 是否创建了 `database/plans/{PlanID}/` 目录
2. 要求 AI 手动创建并写入文件
3. 如果 AI 无法创建文件，要求其输出完整内容，您手动保存

### 问题 3：断点续跑失败

**现象**：恢复执行时从头开始

**原因**：resume.json 未正确读取

**解决方案**：
1. 检查 `database/plans/{PlanID}/resume.json` 是否存在
2. 查看内容是否包含正确的断点信息
3. 要求 AI："请读取 resume.json，从断点位置继续执行"

### 问题 4：模式切换不正确

**现象**：模糊需求触发了轻量化模式

**原因**：信息完整度评分不准确

**解决方案**：
1. 要求 AI重新评估："请重新评估需求信息完整度，按照 WORKFLOW.md 的评分标准"
2. 检查评分标准是否正确应用
3. 如果仍有问题，手动指定模式："请强制使用常规模式执行"

## 最佳实践

### 1. 需求描述技巧

**好的需求描述**：
- ✅ 包含产品目标、目标用户、核心场景
- ✅ 描述具体功能点
- ✅ 说明约束条件（时间、预算、技术等）
- ✅ 提供竞品参考（如果有）

**差的需求描述**：
- ❌ "我想做一个 APP"（太模糊）
- ❌ "类似微信的社交软件"（缺少差异化）
- ❌ "功能越多越好"（缺少优先级）

### 2. 交互节点反馈

**有效反馈**：
- ✅ "目标用户应增加'老年人群体'，因为..."
- ✅ "功能 A 的优先级应该高于功能 B，因为..."
- ✅ "技术选型建议使用 React Native，因为团队熟悉"

**无效反馈**：
- ❌ "都可以"（缺少明确意见）
- ❌ "你决定吧"（放弃决策权）
- ❌ "感觉不对"（缺少具体说明）

### 3. 产物管理

**建议**：
- 每个 Plan 独立目录，避免混淆
- 定期备份 `database/plans/` 目录
- 使用有意义的 Plan ID（如日期 + 序号）
- 为重要产物添加注释说明

### 4. 团队协作

**多人使用建议**：
- 建立统一的命名规范
- 定期同步各 Plan 进度
- 使用 Git 管理产物文件
- 建立需求评审流程

## 常见问题（FAQ）

### Q1: 这个框架需要编程能力吗？

**A**: 不需要。这是一个基于 Prompt 的框架，通过自然语言与 AI 交互。您只需要：
- 会用自然语言描述需求
- 会基本的文件操作
- 会按照提示进行交互

### Q2: 执行一个需求需要多长时间？

**A**: 取决于需求复杂度和执行模式：
- **常规模式**：30-45 分钟（完整执行 13 个 Skill）
- **轻量化模式**：10-15 分钟（跳过 S2 阶段）

### Q3: 可以同时执行多个需求吗？

**A**: 可以。每个 Plan 有独立的 ID 和目录，支持并行执行。建议：
- 为每个 Plan 建立独立目录
- 使用不同的 Plan ID 区分
- 在 `database/index.json` 中维护索引

### Q4: 产物可以直接用于开发吗？

**A**: 可以。产物遵循标准化模板，包含：
- 清晰的功能列表
- 明确的技术选型
- 详细的风险评估
- 可直接对接产品/开发团队

### Q5: 如何保证产物质量？

**A**: 系统通过以下机制保证质量：
- **前置校验**：执行前验证依赖和数据
- **后置校验**：执行后验证格式和内容
- **用户交互**：关键节点人工确认
- **标准化模板**：统一格式，避免遗漏

### Q6: 支持需求变更吗？

**A**: 当前版本不支持自动变更管理。如需变更：
- 方案 1：重新执行整个流程
- 方案 2：手动修改产物文件
- 方案 3：基于原 Plan 创建新版本

### Q7: 可以在其他 IDE 中使用吗？

**A**: 可以。只要有 AI 能力支持，任何 IDE 都可以使用。需要：
- AI 对话功能
- 文件创建/编辑能力
- 项目文件完整复制
