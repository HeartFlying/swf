### 1.3 核心架构变更

#### 架构对比

| 特性 | v1.0（旧版） | v3.0（优化版） | 改进幅度 |
|------|-------------|---------------|---------|
| Agent 数量 | 4 个 | 1 个 | 减少 75% |
| 架构复杂度 | 多 Agent 协作 | 单一 Agent | 大幅简化 |
| 调用开销 | Agent 间调用 | 直接执行 Skill | 效率提升 |
| 用户控制 | 3 个交互节点 | 18 个评审点 | 控制力增强 6 倍 |
| 状态管理 | 复杂（多 Agent） | 简化（单一流程） | 易维护 |
| 日志级别 | 4 个 | 5 个（+REVIEW） | 更完善 |
| 断点类型 | 3 种 | 4 种（+waiting_review） | 更灵活 |

#### 新增用户评审机制

**评审节点**（共 18 个）：
- Plan 评审：1 个（Skill0 完成后）
- Skill 产物评审：13 个（每个 Skill 完成后）
- 阶段汇总评审：4 个（每个阶段完成后）
- 最终报告评审：1 个（所有阶段完成后）

**评审决策类型**：
- ✅ 确认 → 继续执行下一个 Skill
- 📝 修改（小修改）→ 直接修改后重新评审
- 🔧 修改（大修改）→ 返回 Skill 重新执行
- 💡 新增想法 → 更新产物后重新评审

## 三、关键决策记录

### 决策 1：架构简化方案

**决策内容**：移除 3 个子 Agent，采用单一 Coordinator Agent 架构

**决策理由**：
- 减少 Agent 间调用开销
- 简化状态管理复杂度
- 便于后续维护和扩展
- 符合 WORKFLOW.md v2.0 要求

**影响评估**：
- ✅ 正面：架构清晰、效率提升、易维护
- ⚠️ 风险：需要重构所有 Skill 定义文件

### 决策 2：用户评审机制设计

**决策内容**：每个 Skill 输出后都触发用户评审确认

**决策理由**：
- 增强用户对流程的控制力
- 及时发现和纠正偏差
- 支持用户新增想法
- 以用户想法为主导

**影响评估**：
- ✅ 正面：用户满意度提升、产物质量提高
- ⚠️ 风险：交互次数增加（18 个评审点）

### 决策 3：校验和交互内嵌

**决策内容**：将 Validator 和 UserInteraction 的逻辑内嵌到每个 Skill 中

**决策理由**：
- 减少独立 Agent 调用
- 每个 Skill 自包含完整逻辑
- 符合单一职责原则
- 便于 Skill 独立测试

**影响评估**：
- ✅ 正面：Skill 独立性增强、调用链简化
- ⚠️ 风险：需要迁移校验规则到 13 个 Skill
