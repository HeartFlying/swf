#### 3. 痛点识别框架统一

**3 大类痛点**：
- **显性痛点**：用户明确表达的问题和不满（来自用户反馈、调研数据）
- **隐性痛点**：通过分析推断出的潜在问题（来自行为分析、逻辑推理）
- **竞品未解决痛点**：现有竞品未能很好解决的问题（来自竞品分析）

**识别维度**：
- 来源维度：显性/隐性/竞品分析
- 用户维度：核心用户/重要用户/边缘用户
- 频率维度：高频/中频/低频
- 强度维度：严重/中等/轻微

#### 4. 真实性验证框架统一

**4 维度验证**：
- **用户群体验证**：受影响用户类型、用户规模占比、用户重要性
- **场景验证**：场景真实性、场景发生频率、场景覆盖度
- **频率验证**：痛点发生频率、频率稳定性、频率趋势
- **强度验证**：痛苦程度、紧迫程度、替代难度

**验证结果**：
- `已验证`：有充分数据或逻辑支撑
- `待验证`：需要进一步用户调研
- `存疑`：缺乏足够证据，真实性不确定

#### 5. 市场价值评估框架统一

**市场规模估算**：
- 目标用户规模（数量级）
- 市场渗透率预期（%）
- 单用户价值（元/年）
- 市场总价值估算（元/年）

**付费意愿评估**：
- 当前解决成本（时间/金钱）
- 预期付费意愿（元/年）
- 付费意愿等级：`强烈` / `中等` / `弱` / `无`

**价值等级评估**：
- `高价值`：市场规模大 + 付费意愿强烈
- `中价值`：市场规模中等 + 付费意愿中等
- `低价值`：市场规模小 或 付费意愿弱

#### 6. 可行性预判框架统一

**技术可行性**：
- 技术方案描述
- 技术成熟度：`成熟` / `较成熟` / `新兴` / `探索`
- 实现难度：`低` / `中` / `高`
- 技术风险：`低` / `中` / `高`

**资源可行性**：
- 人力投入：`小（<3 人月）` / `中（3-10 人月）` / `大（>10 人月）`
- 资金投入：`小（<50 万）` / `中（50-200 万）` / `大（>200 万）`
- 时间投入：`短（<3 个月）` / `中（3-12 个月）` / `长（>12 个月）`

**时间可行性**：
- 最快实现时间
- 合理实现时间
- 市场窗口期
- 时间风险

**综合可行性**：
- `可行`：技术成熟、资源充足、时间匹配
- `基本可行`：技术可行但有挑战、资源需求中等
- `存疑`：技术或资源存在不确定性
- `不可行`：技术不可行或资源需求过大

#### 7. 质量标准完善

**质量评估框架**（采用 ISO/IEC 25010）：
- 完整性（权重 30%）：所有关键痛点都已识别和验证
- 准确性（权重 25%）：验证结果有充分依据，无主观臆断
- 一致性（权重 20%）：评估标准统一，结论无矛盾
- 可读性（权重 15%）：结构清晰，表达准确，易于理解
- 可追溯性（权重 10%）：关键结论可追溯到数据来源

**检查清单**：
- 完整性检查（7 项）
- 准确性检查（5 项）

**验收标准**：
- 功能性验收（5 项）
- 性能验收（3 项）
- 质量验收（4 项）

**质量综合得分** = 完整性×30% + 准确性×25% + 一致性×20% + 可读性×15% + 可追溯性×10%

**验收标准**：质量综合得分 ≥ 85%
