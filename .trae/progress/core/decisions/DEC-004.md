## Content Details

### Decision Description
在优化 Skill1（需求边界界定）工作流时，发现文档中存在大量 JSON 格式示例，与工作流文档的定位不符。决定将 Skill 文档全面 Markdown 化，统一文档风格。

**核心变更原则**：
1. **输入规范**：采用自然语言描述，明确文件路径和内容要求
2. **输出规范**：使用 Markdown 表格、列表呈现结构化数据
3. **产物格式**：所有产物统一为 Markdown 格式，移除 JSON 产物
4. **状态管理**：统一使用 Todo-List 进行状态追踪，移除 status.json

### Decision Reason
1. **文档定位明确**：Skill 文档是工作流定义，不是 API 接口文档
2. **风格一致性**：与 Skill0（Plan 制定）的文档风格保持一致
3. **可读性提升**：Markdown 表格比 JSON 更易于人工阅读和理解
4. **维护成本降低**：统一格式后，后续 Skill 优化有明确模板可参考

### Impact Scope
- **影响文件**：`skills/s1-requirements/skill1-boundary/SKILL.md`
- **影响版本**：从 2.4 升级到 2.5
- **后续 Skill**：为 Skill2-12 的优化提供文档风格模板

### Specific Changes

#### 1. 输入规范变更
| 变更项 | 变更前 | 变更后 |
|--------|--------|--------|
| 输入格式 | JSON 对象 | 自然语言描述 |
| 输入内容 | planId, planDefinition 等字段 | Plan 定义文件、用户原始需求、Todo-List |
| 前置检查 | JSON 字段校验 | 文件存在性检查、状态检查 |

#### 2. 输出规范变更
| 变更项 | 变更前 | 变更后 |
|--------|--------|--------|
| 产物数量 | 3 个（报告+JSON+status） | 2 个（报告+变更记录） |
| 产物格式 | Markdown + JSON | 纯 Markdown |
| 状态管理 | status.json | todo-list.md |

#### 3. 步骤输出格式变更
| 步骤 | 变更前 | 变更后 |
|------|--------|--------|
| 步骤 3 产品边界 | JSON 格式 | Markdown 表格 |
| 步骤 4 用户边界 | JSON 格式 | Markdown 表格 |
| 步骤 8.5 变更记录 | JSON 格式 | Markdown 表格 |
| 步骤 9 一致性检查 | JSON 格式 | Markdown 表格 |
| 步骤 13 评审记录 | JSON 格式 | Markdown 表格 |

#### 4. 错误处理变更
| 错误码 | 变更前 | 变更后 |
|--------|--------|--------|
| E202 | JSON 格式错误 | Markdown 格式错误 |

### Reference Template

**后续 Skill 优化时应遵循的文档风格模板**：

```markdown
### 1.2 输入规范

**输入来源**：Coordinator Agent 调用，读取前置 Skill 产物

**输入内容**：
- **XXX 文件**：前置 Skill 生成的文档（必填）
  - 文件路径：`artifacts/...`
  - 包含内容：...
- **Todo-List**：当前 Plan 的任务状态追踪文件（必填）
  - 文件路径：`artifacts/plans/{PlanID}/todo-list.md`

**前置状态检查**：
- 检查前置阶段状态是否为 `completed`
- 检查当前任务状态是否为 `pending` 或 `in_progress`

### 1.3 输出规范

**输出产物**：
| 产物 ID | 产物类型 | 文件路径 | 说明 |
|---------|----------|----------|------|
| `{PlanID}-...` | 产物名称 | `artifacts/...` | 产物说明 |

**评审要求**：
- 产物需用户评审确认
- 触发强制评审条件：...
```
