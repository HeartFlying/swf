## 一、背景说明

SKILL0-PLAN 文档经过 v2.0 标准化优化和 v3.0 增强版本优化后，已形成完整的标准规范，包含：

1. **用户交互机制**：步骤 2.5，3 类问题模板，支持多轮对话澄清
2. **用户评审机制**：步骤 8，4 种决策选项，标准化评审流程
3. **Todo-List 更新规则**：4 个更新时机，评审后状态变更逻辑
4. **产物 ID 格式统一**：`{PlanID}-{Stage}-{SkillID}-{序号}`
5. **评审错误处理**：6 类评审/交互相关错误码
6. **用户视角描述**：去除技术字段名，改用场景化描述
7. **统一 Markdown 输出**：所有产物均为.md 格式
8. **Todo-List 统一管理**：整合状态追踪 + 断点续跑 + 评审记录

为此，我们将 SKILL0-PLAN v3.0 确定为示范文档，其他 Skill 优化必须参考此标准。

## 二、核心决策内容

### 决策 1：SKILL0-PLAN v3.0 作为示范文档

**决策内容**：
SKILL0-PLAN v3.0 是其他 12 个 Skill 优化的标准参考文档，必须遵循其规范和格式。

**示范内容包括**：
1. **文档结构**：6 段式结构（元信息、功能描述、执行流程、依赖关系、质量标准、产物规范）
2. **用户交互机制**：步骤 2.5 的触发场景、交互流程、问题模板
3. **用户评审机制**：步骤 8 的评审触发、决策选项、提示模板、结果处理
4. **Todo-List 管理**：更新时机、状态变更、评审记录填写
5. **产物 ID 格式**：`{PlanID}-{Stage}-{SkillID}-{序号}` 标准格式
6. **错误处理**：前置校验、执行过程、后置校验、用户评审、用户交互错误分类
7. **用户视角描述**：输入输出使用自然语言，提供实际示例

**实施范围**：
- Skill1-4（S1 阶段）：需求边界界定、显性需求提取、隐性需求挖掘、需求验证
- Skill5-8（S4 阶段）：需求分类梳理、需求优先级排序、需求风险识别、核心需求提炼
- Skill9-12（S2-S3 阶段）：竞品分析、市场痛点验证、技术可行性评估、轻量化技术选型

### 决策 2：用户交互机制标准

**决策内容**：
所有 Skill 必须添加用户交互环节（步骤 2.5 或步骤 4），用于模糊内容澄清。

**标准规范**：

**触发场景**（4 类）：
- 需求描述中存在模糊词汇（如"类似 XX"、"大概"、"可能"等）
- 关键字段缺失（如未说明目标用户、预算、时间等）
- 检测到矛盾信息（如前后描述不一致）
- 信息完整度评分低于 60 分

**交互流程**（5 步）：
1. 识别模糊/缺失的信息
2. 生成澄清问题（使用标准化问题模板）
3. 等待用户输入
4. 解析用户输入，补充到需求信息对象
5. 如仍不清晰，进行多轮对话（最多 3 轮）

**问题模板**（3 类）：
1. **信息补全请求**：用于关键字段缺失
2. **需求澄清请求**：用于需求描述模糊
3. **方案选择请求**：用于多方案选择

**交互记录保存**：
所有交互记录保存到产物文档的"用户交互记录"章节，包含：
- 交互轮次、交互时间、交互类型
- 问题描述、用户输入、解析结果、处理状态

**实施范围**：
所有 12 个 Skill 都需要添加标准化交互流程，参考 SKILL0-PLAN v3.0 的步骤 2.5。

### 决策 3：用户评审机制标准

**决策内容**：
所有 Skill 必须添加用户评审环节（步骤 8），每个 Skill 输出后触发用户评审确认。

**标准规范**：

**评审触发**：
后置校验通过后立即触发

**用户决策选项**（4 种）：
- **确认**：产物无误，继续执行下一个 Skill
- **修改（小修改）**：直接修改产物内容，重新评审
- **修改（大修改）**：返回 Skill 核心逻辑步骤重新执行
- **新增想法**：更新产物内容，重新评审

**评审提示模板**：
```
【需求分析-{阶段}-{Skill}】- 用户评审

{Skill 名称}已完成，输出产物如下：

{产物表格内容}

---
请评审以上结果：
- 输入「确认」表示无误，继续执行下一个步骤
- 输入「修改」并提供修改意见，格式：「修改：{具体修改内容}」
- 输入「新增」并提出新想法，格式：「新增：{新需求内容}」

示例：
- 确认
- 修改：需求 1 的描述需要更清晰，应该强调...
- 新增：希望能增加用户积分体系功能
```

**评审结果处理**：

| 用户决策 | 处理逻辑 | 状态变更 |
|---------|---------|---------|
| 确认 | 保存产物，更新 Todo-List，继续执行下一个 Skill | 任务状态：已评审，评审状态：已通过 |
| 修改 - 小修改 | 直接修改产物内容，重新展示评审 | 任务状态：执行中，评审状态：需修改 |
| 修改 - 大修改 | 返回 Skill 核心逻辑步骤重新执行 | 任务状态：执行中，评审状态：需重做 |
| 新增想法 | 更新产物内容，重新展示评审 | 任务状态：执行中，评审状态：需修改 |

**评审超时处理**：
- 等待时间：24 小时
- 超时后状态：paused
- 恢复方式：用户输入后自动恢复
- 断点保存：更新 Todo-List 的"断点续跑信息"章节

**评审记录填写**：
每次评审后，在 Todo-List 的"评审记录"章节添加一行：
- 评审轮次：第 N 轮（从 1 开始递增）
- 评审时间：ISO8601 格式时间戳
- 评审结果：通过/需修改
- 评审意见：用户输入的具体意见
- 处理状态：已处理/处理中

**实施范围**：
所有 12 个 Skill 都需要添加标准化评审流程，参考 SKILL0-PLAN v3.0 的步骤 8。

### 决策 4：Todo-List 更新规则标准

**决策内容**：
所有 Skill 必须遵循统一的 Todo-List 更新规则，包含更新时机、状态变更、评审记录填写。

**标准规范**：

**更新时机**（4 个关键节点）：
| 执行阶段 | 更新时机 | 更新内容 |
|---------|---------|---------|
| Skill 执行开始 | 前置校验完成后 | 当前任务状态：待执行 → 执行中 |
| 用户交互后 | 交互完成后 | 更新需求信息（如有补充） |
| Skill 执行完成 | 后置校验通过后 | 当前任务状态：执行中 → 已完成，评审状态：待评审 |
| 用户评审后 | 评审完成后 | 根据评审结果更新状态（见下表） |

**用户评审后的状态更新**：
| 评审结果 | 任务状态 | 评审状态 | 断点续跑信息 |
|---------|---------|---------|-------------|
| 确认 | 已评审 | 已通过 | 可恢复=false |
| 小修改 | 执行中 | 需修改 | 可恢复=true |
| 大修改 | 执行中 | 需重做 | 可恢复=true |
| 新增想法 | 执行中 | 需修改 | 可恢复=true |

**评审记录填写**：
每次评审后，在 Todo-List 的"评审记录"章节添加一行：
- 评审轮次：第 N 轮（从 1 开始递增）
- 评审时间：ISO8601 格式时间戳
- 评审结果：通过/需修改
- 评审意见：用户输入的具体意见
- 处理状态：已处理/处理中

**进度概览更新**：
每次状态更新后，重新计算进度概览：
- 总任务数：固定 13 个 Skill
- 已完成：统计状态为"已完成"和"已评审"的任务数
- 执行中：统计状态为"执行中"的任务数
- 待执行：统计状态为"待执行"的任务数
- 已评审：统计评审状态为"已通过"的任务数
- 进度百分比：(已完成数 / 总任务数) × 100%

**实施范围**：
所有 12 个 Skill 都需要遵循统一的 Todo-List 更新规则，参考 SKILL0-PLAN v3.0 的 2.3 节。

### 决策 5：产物 ID 格式标准

**决策内容**：
所有 Skill 的产物 ID 统一使用标准格式，去除类型后缀。

**标准格式**：
```
{PlanID}-{Stage}-{SkillID}-{序号}
```

**组成部分**：
- PlanID：6 位数字，如 P000001
- Stage：阶段编号，S0/S1/S2/S3/S4
- SkillID：Skill 编号，S00-S12
- 序号：3 位数字，从 001 开始

**示例**：
- `P000001-S1-S01-001` - 需求边界界定产物
- `P000001-S1-S02-001` - 显性需求提取产物
- `P000001-S4-S08-001` - 核心需求提炼产物

**存储路径规范**：
```
database/
├── plans/
│   ├── {PlanID}.md                    # Plan 定义文件
│   └── {PlanID}/
│       └── todo-list.md               # Todo-List（任务跟踪）
└── stages/
    └── {阶段}/
        └── {PlanID}-{Stage}-{SkillID}-{序号}.md  # 阶段产物
```

**实施范围**：
所有 12 个 Skill 的产物 ID 和存储路径都需要遵循此标准。

### 决策 6：错误处理标准

**决策内容**：
所有 Skill 必须包含完整的错误处理规范，包含前置校验、执行过程、后置校验、用户评审、用户交互错误。

**标准分类**：

**前置校验错误**：
| 错误类型 | 错误码 | 处理策略 | 用户提示 |
|---------|-------|---------|---------|
| 输入数据为空 | E001 | 返回错误，要求用户提供 | "请提供{数据名称}" |
| 输入数据过短 | W001 | 返回警告，建议补充 | "建议补充更多细节" |
| 包含敏感信息 | W002 | 返回警告，提醒注意 | "检测到敏感信息，请注意信息安全" |

**执行过程错误**：
| 错误类型 | 错误码 | 处理策略 | 重试次数 |
|---------|-------|---------|---------|
| ID 生成冲突 | E101 | 重新生成，追加随机数 | 最多 3 次 |
| 文件写入失败 | E102 | 记录错误日志，返回失败状态 | 不重试 |

**后置校验错误**：
| 错误类型 | 错误码 | 处理策略 | 重试次数 |
|---------|-------|---------|---------|
| 产物文件不存在 | E201 | 重新执行产物生成 | 1 次 |
| 产物 Markdown 格式错误 | E202 | 重新生成产物文件 | 1 次 |
| 必填字段缺失 | E203 | 补充缺失字段，重新生成 | 1 次 |
| Todo-List 结构错误 | E204 | 重新初始化 Todo-List | 1 次 |

**用户评审错误**：
| 错误类型 | 错误码 | 处理策略 | 重试次数 |
|---------|-------|---------|---------|
| 用户评审未通过 | E301 | 根据评审意见修改产物 | 1 次 |
| 用户评审超时 | W301 | 保持 paused 状态，等待用户输入 | - |
| 用户输入解析失败 | E302 | 请求用户重新输入 | 最多 3 次 |

**用户交互错误**：
| 错误类型 | 错误码 | 处理策略 | 重试次数 |
|---------|-------|---------|---------|
| 用户交互超时 | W401 | 使用默认值继续，标记信息缺失 | - |
| 用户输入无效 | E401 | 重新提问，引导用户正确输入 | 最多 3 次 |
| 多轮对话超过限制 | E402 | 记录信息缺失，继续执行并标记风险 | 不重试 |

**实施范围**：
所有 12 个 Skill 都需要包含完整的错误处理规范，参考 SKILL0-PLAN v3.0 的 2.4 节。
