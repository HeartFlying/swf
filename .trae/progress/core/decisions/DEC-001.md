## 一、背景说明

在 SKILL0-PLAN 优化过程中，我们发现原有文档存在以下问题：
1. **技术视角过重**：使用 JSON 字段名（如 `originalRequirement`）描述输入
2. **格式不统一**：混合使用 JSON 和 Markdown 格式
3. **状态管理分散**：status.json、resume.json、todo-list 多个文件并存
4. **缺少用户示例**：只有数据结构定义，没有实际使用示例

为此，我们制定了一套标准化的文档优化规范，后续所有 SKILL 文档都必须遵循。

## 二、核心决策内容

### 决策 1：用户视角的输入输出描述

**决策内容**：
所有 Skill 的输入输出规范必须从**用户实际使用角度**进行描述，禁止使用技术字段名。

**具体要求**：

- ✅ 使用："需求描述文本"、"补充材料" 等用户友好的自然语言

**输入规范模板**：

### 决策 2：统一 Markdown 输出格式

**决策内容**：
所有 Skill 的输出产物统一为 Markdown 格式（.md），不再使用 JSON 格式。

**具体要求**：
- ✅ Plan 定义文件：`.md` 格式
- ✅ 评分报告：`.md` 格式
- ✅ Todo-List：`.md` 格式
- ✅ 所有中间产物：`.md` 格式
- ❌ 不再创建：`.json` 格式的状态文件、断点文件

**产物格式对照表**：

| 产物类型 | 原格式 | 新格式 | 变更说明 |
|---------|--------|--------|---------|
| Plan 定义 | `.json` | `.md` | 便于阅读和版本管理 |
| 状态追踪 | `status.json` | 整合到 `todo-list.md` | 统一管理 |
| 断点续跑 | `resume.json` | 整合到 `todo-list.md` | 统一管理 |
| 评分报告 | `.md` | `.md` | 保持不变 |
| 其他产物 | 混合 | `.md` | 统一格式 |

**目录结构规范**：
```
artifacts/
├── plans/
│   ├── {PlanID}.md                    # Plan 定义文件
│   └── {PlanID}/
│       └── todo-list.md               # Todo-List（统一状态管理）
└── stages/
    └── {阶段}/
        └── {PlanID}-{Stage}-{SkillID}-{序号}.md  # 阶段产物
```

**实施范围**：
- 所有 Skill 的输出产物定义
- 所有存储路径规范描述
- 所有产物示例

### 决策 5：去除 JSON Schema，改用 Markdown 表格

**决策内容**：
所有文档中去除 JSON Schema 定义，改用 Markdown 表格描述数据结构。

**对比示例**：

**优化前（JSON Schema）**：
```json
{
  "originalRequirement": {
    "type": "string",
    "minLength": 10,
    "description": "用户原始需求文本"
  }
}
```

**优化后（Markdown 表格）**：
```markdown
| 字段 | 类型 | 要求 | 说明 |
|------|------|------|------|
| 需求描述文本 | string | 必填，≥10 字符 | 用户原始需求描述 |
```

**实施范围**：
- 所有 SKILL.md 的输入输出规范
- 所有 template.md 的数据结构描述
- coordinator.md 的产物定义
