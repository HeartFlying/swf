# 执行详情

本 Skill 详细执行步骤参考 SKILL.md Section 3 流程概览。

---

## 详细执行步骤

### 步骤 1：前置校验

**输入验证**：
- 核心需求提炼 (S403产物) 是否存在
- 需求优先级 (S402产物) 是否存在
- Plan 定义文件是否完整

**异常处理**：
- 产物缺失 → 返回 E002，提示前置条件不满足
- 内容不完整 → 返回 E001，请求补充信息

### 步骤 2：识别用户角色

**角色识别维度**：
| 维度 | 说明 | 示例 |
|------|------|------|
| **主要角色** | 直接使用系统的用户 | 注册用户、管理员 |
| **次要角色** | 间接使用系统的用户 | 游客、系统管理员 |
| **外部角色** | 与系统交互的外部实体 | 第三方服务、外部系统 |

### 步骤 3：定义用户活动

**用户活动分类**：
- Backbone 活动：核心业务流程
- Walking skeleton：用户旅程骨架
- 详细活动：具体操作步骤

### 步骤 4：编写用户故事

**标准格式**：
```
作为 [角色]
我想要 [功能]
以便 [价值]
```

**INVEST 原则检查**：
| 原则 | 说明 | 检查项 |
|------|------|--------|
| **I**ndependent | 独立性 | 故事间依赖最小化 |
| **N**egotiable | 可协商 | 实现细节可协商 |
| **V**aluable | 有价值 | 对用户有明确价值 |
| **E**stimable | 可估算 | 可估算工作量 |
| **S**mall | 足够小 | 可在单个迭代完成 |
| **T**estable | 可测试 | 有明确的验收标准 |

### 步骤 5：定义验收标准

**Given-When-Then 格式**：
```
场景: [场景描述]
  Given [前置条件]
  And [更多前置条件]
  When [操作]
  And [更多操作]
  Then [预期结果]
  And [更多预期结果]
```

**示例**：
```
场景: 成功重置密码
  Given 用户已注册且邮箱已验证
  When 用户请求密码重置
  Then 系统发送重置链接到用户邮箱
  And 链接有效期为24小时
```

### 步骤 6：故事点估算

**故事点参考表**：

| 故事点 | 工作量 | 复杂度 | 不确定性 | 说明 |
|--------|--------|--------|----------|------|
| 1 | 简单任务 | 低 | 无 | 1-2小时可完成 |
| 2 | 小功能 | 低 | 低 | 半天可完成 |
| 3 | 标准功能 | 中 | 低 | 1天可完成 |
| 5 | 复杂功能 | 中 | 中 | 2-3天可完成 |
| 8 | 大型功能 | 高 | 中 | 1周可完成 |
| 13 | 史诗级 | 高 | 高 | 需拆分为多个故事 |

### 步骤 7：构建故事地图

**故事地图结构**：
```
用户活动 (Backbone)
    ├── 用户任务 (Walking skeleton)
    │   ├── 故事1 (优先级高)
    │   ├── 故事2 (优先级中)
    │   └── 故事3 (优先级低)
    └── 用户任务2
        └── ...
```

### 步骤 8：定义MVP范围

**MVP识别原则**：
1. 覆盖核心用户活动
2. 优先高价值故事
3. 考虑依赖关系
4. 控制在合理迭代周期内

### 步骤 9：用户交互 - 故事评审

**交互方式**：使用 `option-selection-template.md`

**确认内容**：
- 故事优先级排序
- MVP范围确认
- 迭代计划确认

### 步骤 10：后置校验

**校验内容**：
- 所有核心需求已转换为故事
- 每个故事符合 INVEST 原则
- 验收标准完整明确
- MVP范围合理

### 步骤 11：生成产物

**产物清单**：
1. 用户故事地图
2. 用户故事清单
3. MVP范围定义

### 步骤 12：用户评审

**评审内容**：
- 故事完整性
- 验收标准合理性
- MVP范围合理性

### 步骤 13：更新Todo-List

**更新内容**：
- 标记 S405 完成
- 记录产物路径
- 更新依赖关系
