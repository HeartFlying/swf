## Demo 2：电商系统接口架构设计

### 输入示例

```
架构愿景文档：artifacts/stages/s5/P000002-S5-A01-001.md

数据架构设计文档：artifacts/stages/s5/P000002-S5-A03-001.md

系统特征摘要：
- 客户端类型：Web + 移动端 APP + 小程序
- 实时性要求：高（库存同步、订单状态）
- 数据查询复杂度：复杂（多维度筛选、聚合统计）
- 集成场景：支付网关、物流系统、消息通知
- 性能要求：响应时间 < 200ms，高并发
- 安全等级：敏感（支付信息、用户隐私）
```

### 处理过程

1. **前置校验** -> 检查所有依赖文件存在性 -> 通过
2. **读取前置产物** -> 提取系统特征、模块划分、数据模型
3. **分析接口需求特征** ->
   - 客户端类型：多端 -> 需要 RESTful API
   - 实时性要求：高 -> WebSocket + 消息队列

4. **推导接口技术方案** ->

6. **设计接口规范** ->

7. **设计认证授权方案** ->
   - 认证方案：OAuth2（第三方登录）+ JWT
   - 权限模型：RBAC（管理员/商家/买家）
8. **设计集成接口** ->
   - 支付网关集成（支付宝/微信支付）
   - 物流系统对接
   - 消息通知服务
9. **生成 API 详细设计示例** -> 生成核心接口设计
10. **生成接口架构设计文档** -> P000002-S5-A04-001.md

## 1. 概述

### 1.1 设计目标

设计时间管理 APP 的系统接口架构，包括：
- 移动端 APP 与后端的通信接口
- Web 管理后台与后端的通信接口
- 第三方系统集成接口

### 1.2 设计原则

1. **统一规范**：全系统遵循一致的接口设计规范
2. **版本兼容**：API 变更保持向后兼容
3. **安全优先**：认证授权覆盖所有敏感接口
4. **性能考量**：根据场景选择最优通信方式
5. **可观测性**：接口调用可追踪、可监控

## 4. 接口规范定义

### 4.1 URL 规范

- 基础路径：`/api/v1`
- 资源命名：复数名词，小写字母
- 层级关系：`/users/{id}/tasks`
- 查询参数：`/tasks?status=active&sort=-created_at`

### 4.2 HTTP 方法规范

| 方法 | 用途 | 示例 |
|------|------|------|
| GET | 获取资源 | `GET /api/v1/tasks` |
| POST | 创建资源 | `POST /api/v1/tasks` |
| PUT | 全量更新 | `PUT /api/v1/tasks/{id}` |
| PATCH | 部分更新 | `PATCH /api/v1/tasks/{id}` |
| DELETE | 删除资源 | `DELETE /api/v1/tasks/{id}` |

### 4.3 状态码规范

| 状态码 | 使用场景 |
|--------|----------|
| 200 | 成功响应 |
| 201 | 创建成功 |
| 204 | 删除成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器错误 |

### 4.4 响应格式

**成功响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": { },
  "timestamp": "2026-03-28T10:00:00Z",
  "request_id": "req_xxx"
}
```

**错误响应**：
```json
{
  "code": 400,
  "message": "请求参数错误",
  "errors": [
    {
      "field": "title",
      "message": "标题不能为空",
      "code": "required"
    }
  ]
}
```

## 5. 认证授权设计

### 5.1 认证方案

| 项目 | 方案 |
|------|------|
| 认证方式 | JWT (JSON Web Token) |
| Token 类型 | Access Token + Refresh Token |
| 签名算法 | RS256 |
| Access Token 有效期 | 2 小时 |
| Refresh Token 有效期 | 7 天 |

### 5.2 Token 规范

**Header 传输**：
```
Authorization: Bearer {access_token}
```

**Token 刷新流程**：
```
POST /api/v1/auth/refresh
{
  "refresh_token": "xxx"
}
```

### 5.3 权限模型

| 模型 | 说明 |
|------|------|
| RBAC | 基于角色的访问控制 |

**角色定义**：

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| admin | 系统管理员 | 全部权限 |
| user | 普通用户 | 个人数据权限 |

## 7. API 详细设计示例

### API-001: 创建任务

**基本信息**：
- 接口路径：`POST /api/v1/tasks`
- 接口名称：创建任务
- 所属模块：任务管理
- 优先级：P0（核心接口）

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| title | string | 是 | 任务标题，1-100字符 | "完成项目报告" |
| description | string | 否 | 任务描述 | "需要在周五前完成" |
| due_date | string | 否 | 截止日期 | "2026-04-01T18:00:00Z" |
| priority | string | 否 | 优先级：low/medium/high | "high" |
| tags | array | 否 | 标签列表 | ["工作", "重要"] |

**请求示例**：
```json
{
  "title": "完成项目报告",
  "description": "需要在周五前完成",
  "due_date": "2026-04-01T18:00:00Z",
  "priority": "high",
  "tags": ["工作", "重要"]
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| id | string | 任务 ID |
| title | string | 任务标题 |
| status | string | 任务状态 |
| created_at | string | 创建时间 |

**响应示例**：
```json
{
  "code": 201,
  "message": "success",
  "data": {
    "id": "task_001",
    "title": "完成项目报告",
    "status": "pending",
    "created_at": "2026-03-28T10:00:00Z"
  }
}
```

**错误码**：

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 400001 | 标题不能为空 | 提供任务标题 |
| 400002 | 截止日期格式错误 | 使用 ISO 8601 格式 |
