# S6-A03 UI/UX设计 - 详细执行步骤说明

本文件包含 S6-A03 UI/UX设计 Skill 的详细执行步骤。

---

## 步骤 1：前置校验

**目标**：验证执行本Skill所需的前置条件是否满足

**操作**：
1. 检查前置产物是否存在：
   - 模块详细设计文档：`artifacts/stages/s6/{PlanID}/{PlanID}-S6-A01-001.md`
   - 数据库详细设计文档：`artifacts/stages/s6/{PlanID}/{PlanID}-S6-A02-001.md`
   - 接口架构设计文档：`artifacts/stages/s5/{PlanID}/{PlanID}-S5-A04-001.md`
2. 验证产物状态为 completed
3. 验证产物ID与当前PlanID匹配
4. 检查需求规格说明书是否可访问
5. 检查非功能需求中的可用性要求

**验证规则**：
- 所有前置产物文件必须存在
- 产物状态必须为 completed
- 模块详细设计必须包含业务流程
- 数据库设计必须包含字段信息

**错误处理**：
- E001：前置产物不存在 → 提示用户先执行前置Skill S6-A02
- E002：产物状态非completed → 提示等待前置Skill完成
- E003：产物ID不匹配 → 返回数据一致性错误

---

## 步骤 2：读取前置产物

**目标**：获取UI/UX设计所需的全部输入信息

**操作**：
1. 读取模块详细设计文档，提取：
   - 功能模块清单
   - 业务流程描述
   - 用例描述
   - 核心功能点
2. 读取数据库详细设计文档，提取：
   - 数据实体清单
   - 字段信息（名称、类型、约束）
   - 表关系
3. 读取接口架构设计文档，提取：
   - API清单
   - 接口规范
   - 数据交互模式
4. 读取需求规格说明书，提取：
   - 用户故事
   - 目标用户特征
   - 使用场景
5. 读取非功能需求，提取：
   - 性能要求
   - 可用性要求
   - 多语言需求

**验证规则**：
- 功能模块信息完整
- 业务流程描述清晰
- 目标用户特征明确

**错误处理**：
- E101：文件读取失败 → 重试读取，最多3次
- E102：关键信息缺失 → 标记为风险，使用默认值继续

---

## 步骤 3：分析界面需求

**目标**：分析系统界面需求，确定设计范围

**操作**：
1. 分析功能模块，识别页面需求：
   - 每个功能模块对应的页面
   - 页面类型（列表页/详情页/表单页/ dashboard）
   - 页面优先级（核心/重要/次要）
2. 分析用户角色，确定视角：
   - 不同角色的功能权限
   - 不同角色的界面差异
3. 分析业务流程，识别交互需求：
   - 关键业务流程的界面支持
   - 流程中的决策点
   - 异常处理界面
4. 分析数据需求：
   - 数据展示需求
   - 数据录入需求
   - 数据查询需求
5. 生成界面需求分析报告

**验证规则**：
- 所有功能模块都有对应的页面规划
- 用户角色覆盖完整
- 关键业务流程都有界面支持

**错误处理**：
- E151：功能模块无法映射到页面 → 标记为待确认
- E152：用户角色不明确 → 使用默认角色"普通用户"

---

## 步骤 4：设计信息架构

**目标**：设计系统的导航结构、页面清单和路由体系

**操作**：
1. 设计导航结构：
   - 主导航（顶部导航/侧边栏导航）
   - 子导航（二级菜单/面包屑）
   - 快捷入口（首页快捷功能）
2. 设计页面清单：
   - 页面名称（中文/英文）
   - 页面ID/编码
   - 页面类型
   - 所属模块
   - 访问权限
3. 设计路由体系：
   - URL路径设计（RESTful风格）
   - 路由参数定义
   - 路由权限控制
4. 设计页面层级：
   - 一级页面（入口页面）
   - 二级页面（功能页面）
   - 三级页面（详情/编辑页面）
5. 使用树状图或表格展示信息架构

**验证规则**：
- 所有页面都有唯一标识
- 导航结构清晰，层级合理（不超过3层）
- 路由设计符合RESTful规范

**错误处理**：
- E153：页面命名冲突 → 自动添加模块前缀
- E154：导航层级过深 → 建议扁平化设计

---

## 步骤 5：设计页面布局

**目标**：设计各页面的布局结构和组件摆放

**操作**：
1. 确定布局模式：
   - 整体布局（顶部导航+侧边栏+内容区）
   - 内容区布局（单栏/双栏/三栏）
   - 响应式断点设计
2. 为每个页面设计布局：
   - 页面标题区
   - 操作按钮区
   - 数据展示区
   - 筛选/搜索区
   - 分页/导航区
3. 使用Mermaid或文字描述布局：
   - 区域划分
   - 组件位置
   - 尺寸比例
4. 定义布局规范：
   - 边距规范
   - 间距规范
   - 对齐方式

**验证规则**：
- 所有核心页面都有布局设计
- 布局符合用户操作习惯
- 布局在不同分辨率下可用

**错误处理**：
- E155：布局设计缺失 → 使用默认布局模板
- E156：布局与功能不匹配 → 标记为待确认

---

## 步骤 6：设计界面组件

**目标**：识别并定义界面组件、属性和复用关系

**操作**：
1. 识别原子组件：
   - 基础组件（Button, Input, Select, Checkbox等）
   - 展示组件（Table, Card, List, Badge等）
   - 反馈组件（Modal, Message, Progress等）
2. 识别业务组件：
   - 业务专用组件（用户选择器、日期范围选择器等）
   - 复合组件（搜索表单、数据表格等）
3. 定义组件属性：
   - 组件名称
   - 用途说明
   - 输入属性（Props）
   - 输出事件（Events）
   - 使用示例
4. 分析组件复用关系：
   - 公共组件清单
   - 组件依赖关系
5. 生成组件清单文档

**验证规则**：
- 组件命名规范统一
- 组件属性定义完整
- 复用组件识别充分

**错误处理**：
- E157：组件命名冲突 → 统一命名规范
- E158：组件属性缺失 → 标记为待补充

---

## 步骤 7：设计交互流程

**目标**：设计用户操作流程、状态转换和交互细节

**操作**：
1. 设计主要交互流程：
   - 登录/注册流程
   - 核心业务流程（如创建订单、审批流程）
   - 数据操作流程（增删改查）
2. 使用Mermaid绘制流程图：
   - 用户操作步骤
   - 系统响应
   - 分支判断
   - 异常处理
3. 设计状态转换：
   - 页面状态（加载中/空数据/错误/正常）
   - 组件状态（禁用/启用/选中）
   - 数据状态（草稿/已保存/已提交）
4. 定义交互细节：
   - 按钮点击反馈
   - 表单验证时机
   - 加载状态展示
   - 错误提示方式
5. 设计异常交互：
   - 网络错误处理
   - 权限不足处理
   - 操作失败处理

**验证规则**：
- 所有关键流程都有交互设计
- 状态转换逻辑清晰
- 异常场景有处理方案

**错误处理**：
- E159：交互流程不完整 → 补充缺失流程
- E160：状态转换冲突 → 标记为风险

---

## 步骤 8：设计表单

**目标**：设计表单字段、验证规则和交互行为

**操作**：
1. 识别表单需求：
   - 数据录入表单
   - 查询筛选表单
   - 配置设置表单
2. 设计表单字段：
   - 字段名称（标签）
   - 字段类型（输入框/下拉框/日期等）
   - 字段属性（必填/只读/禁用）
   - 默认值
   - 占位提示（Placeholder）
3. 设计字段验证规则：
   - 必填验证
   - 格式验证（邮箱、手机号等）
   - 长度验证
   - 范围验证
   - 业务规则验证
4. 设计表单布局：
   - 单列/双列/多列布局
   - 字段分组
   - 操作按钮位置
5. 设计表单交互：
   - 实时验证 vs 提交验证
   - 错误提示方式
   - 自动保存机制

**验证规则**：
- 表单字段与数据库字段对应
- 验证规则覆盖所有必填项
- 错误提示信息友好

**错误处理**：
- E161：字段类型无法确定 → 使用默认类型"文本"
- E162：验证规则冲突 → 标记为待确认

---

## 步骤 9：设计响应式布局

**目标**：设计多端适配方案和断点策略

**操作**：
1. 确定适配策略：
   - 桌面优先（Desktop First）
   - 移动优先（Mobile First）
   - 均衡策略
2. 定义断点：
   - 大屏（>= 1440px）
   - 桌面（>= 1024px）
   - 平板（>= 768px）
   - 手机（< 768px）
3. 设计各断点布局变化：
   - 导航栏变化（水平→垂直/折叠）
   - 内容区变化（多列→单列）
   - 表格变化（完整→简化/卡片）
   - 表单变化（双列→单列）
4. 定义响应式规则：
   - 隐藏/显示规则
   - 尺寸调整规则
   - 字体大小调整

**验证规则**：
- 所有核心页面都有响应式设计
- 断点定义合理
- 移动端可用性良好

**错误处理**：
- E163：响应式策略不明确 → 提供选项供用户选择
- E164：移动端布局缺失 → 使用默认适配方案

---

## 步骤 10：设计可访问性

**目标**：确保设计符合WCAG 2.1 AA级标准

**操作**：
1. 设计键盘导航：
   - Tab键顺序
   - 快捷键定义
   - 焦点管理
2. 设计屏幕阅读器支持：
   - ARIA标签（role, aria-label, aria-describedby）
   - 语义化HTML
   - 替代文本（Alt text）
3. 设计视觉可访问性：
   - 色彩对比度（>= 4.5:1）
   - 字体大小可调
   - 不依赖颜色传递信息
4. 设计交互可访问性：
   - 充足的操作时间
   - 错误预防和恢复
   - 清晰的错误提示
5. 生成可访问性检查清单

**验证规则**：
- 所有交互元素都有ARIA标签
- 色彩对比度符合标准
- 键盘导航完整

**错误处理**：
- E165：可访问性检查不通过 → 提供修改建议
- E166：ARIA标签缺失 → 自动补充

---

## 步骤 11：用户交互确认

**目标**：就关键设计决策与用户确认

**操作**：
1. 设计风格确认（如未明确）：
   - 提供风格选项（简洁商务/现代科技/温暖亲和）
   - 展示参考示例
   - 请求用户选择
2. 组件库选择确认：
   - 基于技术栈推荐组件库
   - 提供选项供用户选择
   - 说明各组件库特点
3. 响应式优先级确认：
   - 提供选项（桌面优先/移动优先/均衡策略）
   - 说明各策略适用场景
   - 请求用户确认
4. 交互复杂度确认：
   - 提供简单/丰富交互选项
   - 说明各选项特点
   - 请求用户选择
5. 页面布局争议确认（如有）：
   - 提供多种布局方案
   - 说明各方案优缺点
   - 请求用户选择
6. 记录用户交互结果

**验证规则**：
- 所有关键决策都有明确结果
- 用户交互记录完整保存
- 超时使用默认选项并记录

**错误处理**：
- E301：用户交互超时 → 使用默认选项，记录假设
- E302：用户拒绝选择 → 标记为风险，使用推荐选项

---

4. 生成交互设计章节：
   - 交互流程图
   - 状态转换说明

7. 生成可访问性设计章节

**验证规则**：
- 文档结构完整
- 所有Mermaid图表语法正确

**错误处理**：

- E202：文档格式错误 → 修正格式后重新生成

## 步骤 13：后置校验

**目标**：验证产物完整性和质量

**操作**：
1. 完整性检查：
   - 信息架构完整
   - 页面设计完整
   - 交互设计完整
   - 组件清单完整
   - 响应式设计完整
   - 可访问性设计完整
2. 准确性检查：
   - 页面布局与功能需求一致
   - 表单字段与数据库字段对应
   - 交互流程与业务流程一致
3. 一致性检查：
   - 设计风格统一
   - 组件命名规范统一
   - 色彩体系一致
4. 生成校验报告

**验证规则**：
- 所有检查项通过
- 质量综合得分 >= 85%

**错误处理**：
- E203：后置校验不通过 → 根据问题清单自动修复
- E204：存在无法自动修复的问题 → 标记为风险

## 步骤 15：用户评审

**目标**：提交设计结果供用户评审

**操作**：
1. 展示设计成果摘要：
   - 页面数量统计
   - 组件数量统计
   - 交互流程数量
   - 响应式断点设计
2. 展示关键设计决策
3. 请求用户评审决策：
   - 确认：设计结果满足要求，进入S7实现阶段
   - 小修改：需要调整设计，直接修改产物
   - 大修改：需要重新执行，返回步骤3重新执行
   - 新增想法：有新的设计想法，更新产物
4. 根据评审结果处理：
   - 确认：更新状态，进入下一Skill
   - 修改：根据意见修改产物
   - 重新执行：返回步骤3

**验证规则**：
- 评审记录完整保存
- 用户决策明确记录
- 修改需求清晰可执行

**错误处理**：
- E303：用户评审超时 → 标记为已确认，记录风险
- E304：修改需求不明确 → 请求用户澄清
