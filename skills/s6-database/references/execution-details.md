# S6-A02 数据库详细设计 - 详细执行步骤说明

本文件包含 S6-A02 数据库详细设计 Skill 的详细执行步骤。

---

## 步骤 1：前置校验

**目标**：验证执行本Skill所需的前置条件是否满足

**操作**：
1. 检查前置产物是否存在：
   - 模块详细设计文档：`artifacts/stages/s6/{PlanID}/{PlanID}-S6-A01-001.md`
   - 数据架构设计文档：`artifacts/stages/s5/{PlanID}/{PlanID}-S5-A03-001.md`
   - 接口架构设计文档：`artifacts/stages/s5/{PlanID}/{PlanID}-S5-A04-001.md`
2. 验证产物状态为 completed
3. 验证产物ID与当前PlanID匹配
4. 检查数据库选型是否已确定
5. 检查实体类定义是否完整

**验证规则**：
- 所有前置产物文件必须存在
- 产物状态必须为 completed
- 实体类定义必须包含名称和属性列表
- 数据库类型必须已确定

**错误处理**：
- E001：前置产物不存在 → 提示用户先执行前置Skill S6-A01
- E002：产物状态非completed → 提示等待前置Skill完成
- E003：实体类定义不完整 → 请求补充实体信息
- E004：数据库选型未确定 → 提示先完成S5-A03数据架构设计
- E005：产物ID不匹配 → 返回数据一致性错误

---

## 步骤 2：读取前置产物

**目标**：获取数据库详细设计所需的全部输入信息

**操作**：
1. 读取模块详细设计文档，提取：
   - 实体类定义（类名、属性、类型、约束）
   - 类关系（关联、聚合、组合、继承）
   - 数据访问需求
2. 读取数据架构设计文档，提取：
   - 数据模型定义
   - 存储方案
   - 数据库选型
3. 读取接口架构设计文档，提取：
   - 数据访问模式
   - 查询需求
4. 读取非功能需求，提取：
   - 性能要求
   - 容量预估
   - 备份要求

**验证规则**：
- 实体类定义完整可读
- 数据模型与实体类对应关系清晰
- 数据库选型信息明确

**错误处理**：
- E101：文件读取失败 → 重试读取，最多3次
- E102：文件解析失败 → 标记为风险，使用部分数据继续

---

## 步骤 3：分析数据实体

**目标**：分析实体特征，为表结构设计提供依据

**操作**：
1. 遍历所有实体类，分析特征：
   - 实体类型识别（主表/从表/关联表/字典表）
   - 数据量预估（基于业务场景）
   - 访问频率分析（读多/写多/读写均衡）
   - 关联关系分析（一对一/一对多/多对多）
2. 识别特殊实体：
   - 需要分区的表（大数据量）
   - 需要缓存的表（高频读取）
   - 需要审计的表（重要业务数据）
3. 生成实体分析报告

**验证规则**：
- 所有实体都有类型标识
- 数据量预估有依据
- 关联关系无循环依赖

**错误处理**：
- E151：实体类型无法识别 → 使用默认类型"主表"
- E152：数据量预估缺失 → 使用默认值，标记为风险

---

## 步骤 4：设计表结构

**目标**：将实体类映射为数据库表结构

**操作**：
1. 表命名设计：
   - 小写字母，下划线分隔
   - 复数名词形式
   - 添加模块前缀（如需要）
2. 字段设计：
   - 字段命名（snake_case）
   - 字段类型选择（基于数据库类型和业务场景）
   - 约束定义（NOT NULL, UNIQUE, DEFAULT）
   - 注释说明（中文名称、用途）
3. 主键设计：
   - 自增ID（BIGINT AUTO_INCREMENT）
   - 或UUID（CHAR(36)）
4. 外键设计：
   - 外键字段命名（{table}_id）
   - 外键约束定义
5. 审计字段设计：
   - created_at（创建时间）
   - updated_at（更新时间）
   - created_by（创建人）
   - updated_by（更新人）
   - deleted_at（软删除标记）
6. 生成表结构清单

**验证规则**：
- 表命名符合规范
- 所有字段都有类型和注释
- 主键设计合理
- 审计字段齐全

**错误处理**：
- E153：字段类型映射失败 → 请求用户确认字段类型
- E154：表命名冲突 → 自动调整命名，添加前缀/后缀

---

## 步骤 5：设计索引

**目标**：基于查询需求和性能要求设计合理的索引策略

**操作**：
1. 分析查询需求：
   - 高频查询字段
   - 排序字段
   - 关联查询字段
   - 范围查询字段
2. 设计主键索引：
   - 聚簇索引（默认主键）
3. 设计唯一索引：
   - 业务唯一字段（如用户名、邮箱）
4. 设计普通索引：
   - 高频查询条件字段
   - 外键字段
   - 排序字段
5. 设计复合索引：
   - 多字段联合查询场景
   - 遵循最左前缀原则
6. 评估索引数量：
   - 避免过多索引影响写入性能
7. 生成索引设计清单

**验证规则**：
- 所有高频查询都有索引支持
- 索引命名规范（idx_{table}_{fields}）
- 索引数量合理（不超过字段数50%）

**错误处理**：
- E155：索引数量过多 → 提示优化，建议使用复合索引
- E156：索引字段选择冲突 → 标记为待确认

---

## 步骤 6：设计视图

**目标**：设计简化查询和数据脱敏的视图

**操作**：
1. 识别视图需求：
   - 简化复杂查询（多表关联）
   - 数据脱敏（隐藏敏感字段）
   - 统计聚合（汇总数据）
   - 权限隔离（行级过滤）
2. 设计视图结构：
   - 视图命名（view_{purpose}）
   - SELECT语句设计
   - 字段别名和计算字段
3. 评估视图性能：
   - 避免复杂嵌套
   - 确保底层表有适当索引
4. 生成视图定义清单

**验证规则**：
- 视图命名符合规范
- 视图查询性能可接受
- 无循环视图依赖

**错误处理**：
- E157：视图查询过于复杂 → 建议拆分为多个视图
- E158：视图依赖缺失 → 标记为风险

---

## 步骤 7：设计存储过程

**目标**：设计复杂批量处理和事务性操作的存储过程

**操作**：
1. 识别存储过程需求：
   - 复杂业务逻辑（多步骤操作）
   - 批量数据处理
   - 事务性操作（保证数据一致性）
   - 定时任务（数据清理、统计）
2. 设计存储过程：
   - 过程命名（sp_{module}_{action}）
   - 输入参数定义
   - 输出参数定义
   - 业务逻辑步骤
   - 异常处理逻辑
   - 事务控制（BEGIN TRANSACTION）
3. 评估存储过程使用范围：
   - 避免过度使用（业务逻辑尽量在应用层）
4. 生成存储过程清单

**验证规则**：
- 存储过程命名符合规范
- 有明确的事务控制
- 有异常处理逻辑

**错误处理**：
- E159：存储过程逻辑过于复杂 → 建议拆分或移至应用层
- E160：事务范围过大 → 建议缩小事务范围

---

## 步骤 8：设计触发器

**目标**：设计审计日志和数据一致性维护的触发器

**操作**：
1. 识别触发器需求：
   - 审计日志（记录数据变更）
   - 数据一致性（级联更新/删除）
   - 数据验证（复杂业务规则）
   - 自动计算（衍生字段）
2. 设计触发器：
   - 触发器命名（trg_{table}_{timing}_{action}）
   - 触发时机（BEFORE/AFTER）
   - 触发事件（INSERT/UPDATE/DELETE）
   - 触发逻辑
3. 评估触发器影响：
   - 避免触发器嵌套
   - 评估性能影响
4. 生成触发器清单

**验证规则**：
- 触发器命名符合规范
- 触发逻辑清晰
- 无触发器循环调用

**错误处理**：
- E161：触发器逻辑冲突 → 标记为风险，建议人工评估
- E162：触发器性能影响大 → 建议改用应用层实现

---

## 步骤 9：设计分区

**目标**：针对大数据量表设计合理的分区策略

**操作**：
1. 识别分区需求：
   - 数据量超过分区阈值（如1000万条）
   - 有明显的时间或范围特征
2. 选择分区类型：
   - 范围分区（RANGE，按时间/ID范围）
   - 列表分区（LIST，按离散值）
   - 哈希分区（HASH，均匀分布）
   - 复合分区（RANGE + HASH）
3. 设计分区键：
   - 选择查询条件中常用的字段
   - 确保数据分布均匀
4. 设计分区策略：
   - 分区数量
   - 分区命名规则
   - 历史数据归档策略
5. 生成分区设计清单

**验证规则**：
- 分区策略适合数据特征
- 分区键选择合理
- 数据分布预估均匀

**错误处理**：
- E163：分区策略不适用 → 标记为风险，建议人工评估
- E164：分区键选择不当 → 提供替代方案

---

## 步骤 10：设计数据迁移

**目标**：设计数据迁移脚本和初始化数据

**操作**：
1. 设计初始化数据：
   - 字典表数据（状态码、配置项）
   - 系统配置数据
   - 默认用户/角色数据
2. 设计数据迁移脚本：
   - 表结构创建脚本（DDL）
   - 初始化数据插入脚本（DML）
   - 数据迁移脚本（从旧系统迁移）
3. 设计数据清理脚本：
   - 测试数据清理
   - 历史数据归档
4. 生成迁移脚本清单

**验证规则**：
- 初始化数据完整
- 脚本可重复执行（幂等性）
- 有数据备份建议

**错误处理**：
- E165：初始化数据缺失 → 标记为待补充
- E166：迁移脚本有冲突 → 提示修改

   - 说明读性能 vs 写性能权衡

   - 请求用户确认

**验证规则**：
- 所有关键决策都有明确结果
- 用户交互记录完整保存
- 超时使用默认选项并记录

**错误处理**：
- E301：用户交互超时 → 使用默认选项，记录假设
- E302：用户拒绝选择 → 标记为风险，使用推荐选项

## 步骤 13：生成DDL脚本

**目标**：生成可直接执行的建表SQL脚本

**操作**：
1. 生成建表语句：
   - CREATE TABLE语句
   - 字段定义
   - 约束定义（主键、外键、唯一约束）
   - 注释（COMMENT）
2. 生成建索引语句：
   - CREATE INDEX语句
3. 生成建视图语句：
   - CREATE VIEW语句
4. 生成存储过程语句：
   - CREATE PROCEDURE语句
5. 生成触发器语句：
   - CREATE TRIGGER语句
6. 生成初始化数据插入语句
7. 按依赖顺序组织脚本

**验证规则**：
- SQL语法正确
- 依赖顺序正确（先建表，再建外键）
- 脚本可执行

**错误处理**：
- E203：DDL生成失败 → 重试生成
- E204：SQL语法错误 → 自动修正或标记为风险

## 步骤 14：设计质量检查

**目标**：自动检查数据库设计质量

**操作**：
1. 命名规范检查：
   - 表命名规范
   - 字段命名规范
   - 索引命名规范
2. 范式合规检查：
   - 第一范式（原子性）
   - 第二范式（完全依赖）
   - 第三范式（消除传递依赖）
3. 主键设计检查：
   - 所有表都有主键
   - 主键类型合理
4. 索引合理性检查：
   - 索引覆盖高频查询
   - 无重复索引
   - 索引数量合理
5. 生成质量检查报告

**验证规则**：
- 所有检查项都有明确结果
- 严重问题必须修复
- 质量评分 >= 85%

**错误处理**：
- E205：质量检查不通过 → 根据问题清单自动修复
- E206：存在无法自动修复的问题 → 标记为风险
