# S5-A01 Demo 示例

## 示例 1：企业Web应用架构愿景定义

### 输入

```
Plan 定义文件：artifacts/plans/P000001.md
- Plan ID: P000001
- 执行模式：常规模式

需求规格说明书摘要：
"开发一个面向中小企业的项目管理系统，支持多部门协作，
需要与现有OA系统集成，预计用户规模500人，要求响应时间<2秒，
数据安全等级为敏感级别。"

前置Skill产物：S1-S4阶段已完成
```

### 处理过程

1. **前置校验** → 所有文件存在，校验通过
2. **读取需求产物** → 提取系统特征信息
3. **识别系统特征**：
   - 系统类型：企业Web应用
   - 用户规模：部门级（约500用户）
   - 数据特征：关系型数据为主，协作数据
   - 性能要求：中等（响应<2秒，约200并发）
   - 集成需求：与OA系统集成（中等复杂度）
   - 安全等级：敏感级别
4. **推导架构方向**：
   - 架构风格：分层架构（推荐）
   - 技术策略：应用集群 + 数据库优化
   - 存储方案：关系数据库
5. **识别决策点**：
   - 架构风格确认
   - 技术栈选择
   - 部署方式选择
6. **用户交互确认**：
   - 用户选择分层架构 + 单体部署
   - 用户确认技术栈：Spring Boot + PostgreSQL
7. **生成架构愿景** → 生成 P000001-S5-A01-001.md
8. **后置校验** → 校验通过
9. **用户评审** → 等待用户确认

### 输出

```markdown
# 架构愿景文档 - P000001-S5-A01-001

## 1. 系统定位
- 系统名称：企业项目管理系统
- 系统类型：企业Web应用
- 目标用户：中小企业员工、部门经理、系统管理员
- 核心价值：提升项目协作效率，实现跨部门信息共享

## 2. 系统特征分析
- 用户规模：部门级（约500用户）
- 数据特征：关系型数据为主，协作数据中等复杂度
- 性能要求：中等并发（约200并发，响应<2秒）
- 集成需求：与OA系统集成（中等复杂度）
- 安全等级：敏感级别

## 3. 架构目标
### 3.1 功能性目标
- 支持项目创建、任务分配、进度跟踪
- 支持多部门协作和权限管理
- 支持与OA系统的数据对接

### 3.2 非功能性目标
- 性能目标：响应时间<2秒，支持200并发
- 可用性目标：99.9%（年停机时间<8.76小时）
- 安全目标：敏感数据加密存储，细粒度权限控制
- 可扩展性目标：支持平滑扩展到1000用户

## 4. 关键架构决策
| 决策项 | 决策结果 | 决策理由 | 决策方式 |
|--------|----------|----------|----------|
| 架构风格 | 分层架构 | 适合当前规模，易于维护 | 用户选择 |
| 技术栈 | Spring Boot + PostgreSQL | 团队熟悉，生态成熟 | 用户选择 |
| 部署方式 | 传统部署（单体） | 初期简单，可平滑演进 | 用户选择 |

## 5. 架构原则
- 原则1：简单优先，避免过度设计
- 原则2：关注点分离，层次清晰
- 原则3：安全内置，权限细粒度

## 6. 风险与假设
### 6.1 架构风险
| 风险描述 | 风险等级 | 缓解策略 |
|----------|----------|----------|
| OA系统接口不稳定 | 中 | 设计适配层，增加重试机制 |
| 并发峰值超出预期 | 低 | 预留集群扩展能力 |

### 6.2 设计假设
| 假设描述 | 验证方式 |
|----------|----------|
| 用户规模3年内不超过1000人 | 与用户确认 |
| OA系统提供REST API | 与技术团队确认 |
```

## 示例 2：高并发互联网应用架构愿景定义

### 输入

```
Plan 定义文件：artifacts/plans/P000002.md
- Plan ID: P000002
- 执行模式：常规模式

需求规格说明书摘要：
"开发一个面向C端用户的电商平台，预计日活用户100万，
峰值QPS达到10000，要求高可用性（99.99%），
支持秒杀活动，数据需要强一致性。"

前置Skill产物：S1-S4阶段已完成
```

### 处理过程

1. **前置校验** → 所有文件存在，校验通过
2. **读取需求产物** → 提取系统特征信息
3. **识别系统特征**：
   - 系统类型：高并发互联网应用
   - 用户规模：互联网级（日活100万）
   - 数据特征：交易数据为主，需要强一致性
   - 性能要求：极高（峰值QPS 10000）
   - 集成需求：支付系统、物流系统
   - 安全等级：敏感级别（交易数据）
4. **推导架构方向**：
   - 架构风格：微服务架构（推荐）
   - 技术策略：分库分表，分布式缓存，消息队列
   - 存储方案：多存储组合
5. **识别决策点**：
   - 架构风格确认（微服务 vs 单体）
   - 数据一致性策略
   - 秒杀方案选择
6. **用户交互确认**：
   - 用户选择微服务架构
   - 用户选择强一致性（交易核心）
   - 用户选择独立秒杀服务
7. **生成架构愿景** → 生成 P000002-S5-A01-001.md
8. **后置校验** → 校验通过
9. **用户评审** → 等待用户确认

### 输出

```markdown
# 架构愿景文档 - P000002-S5-A01-001

## 1. 系统定位
- 系统名称：电商平台
- 系统类型：高并发互联网应用
- 目标用户：C端消费者、商家、运营人员
- 核心价值：提供流畅的购物体验，支撑高并发交易

## 2. 系统特征分析
- 用户规模：互联网级（日活100万）
- 数据特征：交易数据为主，需强一致性
- 性能要求：极高（峰值QPS 10000）
- 集成需求：支付系统、物流系统、推荐系统
- 安全等级：敏感级别（交易数据）

## 3. 架构目标
### 3.1 功能性目标
- 支持商品展示、搜索、购物车、下单支付
- 支持秒杀活动，高并发抢购
- 支持订单管理、物流跟踪

### 3.2 非功能性目标
- 性能目标：峰值QPS 10000，响应时间<500ms
- 可用性目标：99.99%（年停机时间<52.6分钟）
- 安全目标：交易数据加密，支付安全
- 可扩展性目标：支持水平扩展

## 4. 关键架构决策
| 决策项 | 决策结果 | 决策理由 | 决策方式 |
|--------|----------|----------|----------|
| 架构风格 | 微服务架构 | 支持高并发，独立扩展 | 用户选择 |
| 数据一致性 | 强一致性（交易核心） | 保证交易正确性 | 用户选择 |
| 秒杀方案 | 独立秒杀服务 | 隔离流量，保护核心 | 用户选择 |

## 5. 架构原则
- 原则1：服务拆分按业务域
- 原则2：核心交易强一致性，非核心最终一致性
- 原则3：缓存优先，异步削峰

## 6. 风险与假设
### 6.1 架构风险
| 风险描述 | 风险等级 | 缓解策略 |
|----------|----------|----------|
| 微服务复杂度高 | 高 | 完善监控和运维体系 |
| 分布式事务处理 | 高 | 使用分布式事务框架 |
| 秒杀流量冲击 | 中 | 限流降级，队列削峰 |

### 6.2 设计假设
| 假设描述 | 验证方式 |
|----------|----------|
| 用户量增长平稳 | 与运营团队确认 |
| 云服务资源充足 | 与运维团队确认 |
```

## 示例 3：用户交互示例

### 交互场景：架构风格选择

**系统输出**：
```
【方案选择请求】

基于需求分析，系统具有以下特征：
- 系统类型：企业Web应用
- 用户规模：部门级（约500用户）
- 性能要求：中等并发（约200并发）

推荐架构方案：
A. 分层架构 + 单体部署（推荐）
   - 适合当前规模，开发效率高
   - 未来可平滑演进为微服务

B. 微服务架构 + 容器部署
   - 适合未来扩展，但初期复杂度高
   - 需要DevOps能力支持

请选择架构方案（A/B）：
```

**用户输入**：`A`

**系统处理**：
- 记录用户选择：分层架构 + 单体部署
- 更新架构愿景文档
- 继续下一步骤

---

### 交互场景：可用性指标澄清

**系统输出**：
```
【信息澄清请求】

在[架构愿景定义]过程中，发现以下信息需要澄清：

问题描述：需求中提到"系统需要支持高可用"，但未明确可用性指标
当前上下文：正在定义非功能性目标
可能理解：
  A. 99.9%（年停机时间 < 8.76小时）- 一般业务系统
  B. 99.99%（年停机时间 < 52.6分钟）- 重要业务系统
  C. 99.999%（年停机时间 < 5.26分钟）- 核心业务系统
  D. 其他（请说明）

请选择正确的理解（输入A/B/C/D）：
```

**用户输入**：`B`

**系统处理**：
- 记录用户选择：99.99%可用性
- 更新架构目标中的可用性指标
- 继续下一步骤

```
基于需求分析，做出以下假设：

假设1：系统主要面向内部用户，不需要考虑CDN加速

请确认以上假设是否成立（是/否）：
如有不成立的假设，请说明：
```

**系统处理**：
