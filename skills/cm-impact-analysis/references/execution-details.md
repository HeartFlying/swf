## 步骤 1：变更解析

### 1.1 解析变更内容

从用户输入中提取以下信息：

| 字段 | 说明 | 示例 |

| 变更原因 | 为什么要变更 | "提升用户活跃度" |

## 步骤 2：变更类型判定

### 2.1 关键词匹配

使用关键词库判定变更类型：

**需求变更关键词**：
- 功能、特性、需求、用户、业务、流程、场景
- 新增、删除、修改、优化、调整

**架构变更关键词**：
- 架构、服务、组件、模块、分层、解耦
- 微服务、单体、分布式、集群

**设计变更关键词**：
- 数据库、表、字段、索引、SQL
- 接口、API、类、方法、算法
- 页面、UI、交互、布局

### 2.2 判定规则

```
IF 匹配需求关键词 AND 不涉及架构/设计关键词:
    类型 = 需求变更
ELSE IF 匹配架构关键词:
    类型 = 架构变更
ELSE IF 匹配设计关键词:
    类型 = 设计变更
ELSE:
    请求用户明确变更类型
```

### 2.3 判定结果输出

```markdown
## 变更类型判定

**判定结果**: {需求变更/架构变更/设计变更}
**判定依据**: {匹配的关键词}
**置信度**: {高/中/低}
```

## 步骤 4：级联影响识别

### 4.1 直接影响识别

根据变更类型识别直接受影响的元素：

**需求变更**：
- 直接修改/新增/删除的需求项
- 与这些需求项直接关联的 Skill 产物

**架构变更**：
- 直接修改的架构组件
- 依赖该组件的其他组件

**设计变更**：
- 直接修改的设计元素
- 依赖该元素的其他元素

### 4.2 间接影响识别

基于依赖图谱进行级联分析：

```python
def identify_cascade_impacts(initial_elements, depth=0, max_depth=5):
    """
    识别级联影响

    Args:
        initial_elements: 直接受影响的元素列表
        depth: 当前递归深度
        max_depth: 最大递归深度

    Returns:
        impacts: 所有受影响的元素（按层级分组）
    """
    if depth >= max_depth:
        return {}

    impacts = {depth: initial_elements}
    next_level = []

    for element in initial_elements:
        # 获取该元素影响的其他元素
        impacted = get_impacted_elements(element)
        next_level.extend(impacted)

    if next_level:
        impacts.update(identify_cascade_impacts(next_level, depth + 1, max_depth))

    return impacts
```

## 步骤 5：影响范围计算

### 5.1 计算影响系数

```
影响系数 = Σ(直接受影响元素 × 1.0) +
          Σ(间接受影响元素 × 0.5) +
          级联深度 × 0.3

其中：
- 直接受影响元素：用户明确指定的变更元素
- 间接受影响元素：通过依赖分析识别的影响元素
- 级联深度：依赖链的最大深度
```

### 5.2 影响范围判定

| 影响系数 | 影响等级 | 处理策略 |
|----------|----------|----------|
| < 3 | 轻度 | 仅重执行当前阶段 |
| 3-8 | 中度 | 重执行当前及后续阶段 |
| > 8 | 重度 | 建议拆分变更或全量重执行 |

### 5.3 影响范围输出

```markdown
## 影响范围评估

**级联深度**: 3 层

### 受影响阶段

|------|----------|------|
| S4 | 重度 | 需求变更直接作用于S4 |
| S5 | 中度 | 架构需适配新需求 |
```
