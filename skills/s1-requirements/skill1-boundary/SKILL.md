## 基本信息

| 项目 | 内容 |
|-----|------|
| **Skill编号** | S1-S01 |
| **Skill名称** | 需求边界界定 |

## 功能描述

### 核心职责

Skill1负责明确需求分析的边界范围，包括：
1. **产品边界界定**：明确产品做什么、不做什么
2. **用户边界界定**：明确目标用户群体及其特征
3. **场景边界界定**：明确产品使用的核心场景和排除场景
4. **时间边界界定**：明确项目的时间范围和阶段划分
5. **资源边界界定**：明确可用资源和资源限制

### 输入输出

**输入**：
- Plan定义文件 (`database/plans/{PlanID}.json`)
- 用户原始需求文本
- 信息完整度评分报告（参考）

**输出**：
- 需求边界界定报告 (`database/stages/s1/{PlanID}-S1-S01-001-boundary.md`)
- 边界定义JSON (`database/stages/s1/{PlanID}-S1-S01-001-boundary.json`)
- 更新status.json中S1-S01状态

---

## 执行流程

```
读取Plan定义和原始需求
    ↓
分析产品边界（做什么/不做什么）
    ↓
分析用户边界（目标用户/非目标用户）
    ↓
分析场景边界（核心场景/排除场景）
    ↓
分析时间边界（项目阶段/里程碑）
    ↓
分析资源边界（可用资源/限制）
    ↓
生成分层边界定义
    ↓
识别边界模糊点并标记风险
    ↓
输出边界界定报告和JSON
    ↓
更新状态文件
    ↓
返回执行结果
```

## 详细规范

### 1. 产品边界界定

**必须包含的要素**：

| 要素 | 说明 | 示例 |
|------|------|------|
| **核心功能域** | 产品必须实现的功能范围 | 任务管理、日程安排 |
| **辅助功能域** | 产品应该具备的辅助功能 | 数据备份、用户设置 |
| **扩展功能域** | 未来可能扩展的功能 | AI智能推荐、社交分享 |
| **明确排除域** | 明确不做的功能 | 即时通讯、电商交易 |
| **边界待定域** | 需要进一步确认的功能 | 第三方集成、高级分析 |

**边界定义格式**：
```json
{
  "productBoundary": {
    "coreDomain": ["功能1", "功能2"],
    "auxiliaryDomain": ["功能3", "功能4"],
    "extensionDomain": ["功能5", "功能6"],
    "excludedDomain": ["功能7", "功能8"],
    "pendingDomain": ["功能9"],
    "rationale": "边界划分理由"
  }
}
```

### 2. 用户边界界定

**用户分层模型**：

| 层级 | 定义 | 特征描述 | 优先级 |
|------|------|----------|--------|
| **核心用户** | 产品主要服务的用户群体 | 使用频率高、需求明确 | P0 |
| **次要用户** | 偶尔使用或间接使用的用户 | 使用频率中、需求较明确 | P1 |
| **边缘用户** | 可能使用但非目标的用户 | 使用频率低、需求模糊 | P2 |
| **排除用户** | 明确不为这类用户服务 | 不在服务范围内 | - |

**用户画像要素**：

```json
{
  "userBoundary": {
    "coreUsers": {
      "demographics": "人口统计特征",
      "psychographics": "心理特征",
      "behaviors": "行为特征",
      "needs": "核心需求",
      "painPoints": "痛点"
    },
    "secondaryUsers": {...},
    "excludedUsers": [...],
    "userScenarios": ["场景1", "场景2"]
  }
}
```

### 3. 场景边界界定

**场景分类框架**：

| 场景类型 | 定义 | 示例 |
|----------|------|------|
| **核心场景** | 产品主要解决的使用场景 | 大学生在图书馆制定学习计划 |
| **高频场景** | 用户经常遇到的场景 | 每日任务打卡 |
| **低频场景** | 偶尔发生但重要的场景 | 学期初制定学期计划 |
| **边缘场景** | 可能发生但优先级低的场景 | 临时调整计划 |
| **排除场景** | 明确不处理的场景 | 团队协作场景（V1.0不做） |

**场景描述模板**：
```
场景名称: [名称]
场景类型: [核心/高频/低频/边缘/排除]
用户角色: [谁]
使用环境: [在哪里]
使用时机: [什么时候]
用户目标: [想要达成什么]
当前痛点: [遇到什么困难]
产品价值: [如何解决问题]
```

### 4. 时间边界界定

**项目阶段划分**：

| 阶段 | 时间范围 | 里程碑 | 交付物 |
|------|----------|--------|--------|
| **MVP阶段** | 0-3个月 | 核心功能可用 | 可运行的原型 |
| **V1.0阶段** | 3-6个月 | 正式版本发布 | 完整功能产品 |
| **V2.0阶段** | 6-12个月 | 功能完善 | 增强版产品 |
| **长期规划** | 12个月+ | 生态建设 | 平台化产品 |

### 5. 资源边界界定

**资源类型清单**：

| 资源类型 | 可用资源 | 限制条件 | 风险等级 |
|----------|----------|----------|----------|
| **人力资源** | 团队规模、角色分工 | 技能缺口、时间限制 | 高/中/低 |
| **技术资源** | 技术栈、基础设施 | 技术债务、兼容性 | 高/中/低 |
| **资金资源** | 预算范围、资金来源 | 预算约束、ROI要求 | 高/中/低 |
| **外部资源** | 第三方服务、合作伙伴 | 依赖风险、成本波动 | 高/中/低 |

## 错误处理

### 前置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| Plan定义文件不存在 | E001 | 返回错误，要求先执行Skill0 |
| 原始需求缺失 | E002 | 返回错误，要求补充需求 |
| 信息完整度过低 | E003 | 警告，建议补充信息后再执行 |

### 执行过程错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 边界定义冲突 | E101 | 标记冲突点，请求人工确认 |
| 无法识别边界 | E102 | 标记为待定，继续执行 |
| 文件写入失败 | E103 | 重试3次，失败则返回错误 |

### 后置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 产物文件缺失 | E201 | 重新生成产物 |
| JSON格式错误 | E202 | 修复格式后重新输出 |
| 必填字段缺失 | E203 | 补充缺失字段 |

### 与Validator Agent的协作

- **前置校验**：检查Plan定义和原始需求完整性
- **后置校验**：检查边界定义JSON格式和必填字段

### 与UserInteraction Agent的协作

**交互触发条件**：
- 当边界模糊点较多时，请求用户确认边界划分
- 当存在重大边界冲突时，请求用户决策

## 执行示例

### 示例: 时间管理APP边界界定

**输入**：
```
我想开发一个面向大学生的时间管理APP，帮助用户管理学习计划和任务。
核心功能包括：任务创建、日程安排、番茄钟、学习统计。
目标用户是18-25岁的大学生，主要在校园场景使用。
```

**输出摘要**：

**产品边界**：
- 核心域：任务管理、日程安排、番茄钟、学习统计
- 辅助域：数据备份、提醒通知、用户设置
- 扩展域：AI智能推荐、社交分享、多平台同步
- 排除域：即时通讯、电商交易、内容社区
- 待定域：第三方日历集成、团队协作功能

**用户边界**：
- 核心用户：18-25岁在校大学生，有明确时间管理需求
- 次要用户：研究生、职场新人
- 排除用户：中学生、无时间管理需求的用户

**场景边界**：
- 核心场景：图书馆学习、宿舍自习、课堂笔记
- 高频场景：每日任务打卡、周计划制定
- 排除场景：团队协作、企业级项目管理
