## 基本信息

| 项目 | 内容 |
|-----|------|
| **Skill编号** | S1-S02 |
| **Skill名称** | 显性需求提取 |
| **所属阶段** | S1 - 需求边界与原始采集 |
| **执行顺序** | S1阶段第2个执行 |
| **执行模式** | 常规模式/轻量化模式均执行 |

---

## 功能描述

### 核心职责

Skill2负责从用户原始需求中提取和结构化显性需求，包括：
1. **功能需求提取**：识别用户明确提出的功能点
2. **非功能需求提取**：识别性能、安全、体验等要求
3. **业务规则提取**：识别业务流程和规则约束
4. **数据需求提取**：识别数据存储和处理需求
5. **接口需求提取**：识别与外部系统的集成需求

### 输入输出

**输入**：
- Plan定义文件
- 需求边界界定报告（S1-S01产物）
- 用户原始需求文本

**输出**：
- 显性需求清单报告 (`database/stages/s1/{PlanID}-S1-S02-001-explicit.md`)
- 显性需求JSON (`database/stages/s1/{PlanID}-S1-S02-001-explicit.json`)
- 更新status.json中S1-S02状态

---

## 执行流程

```
读取边界界定报告和原始需求
    ↓
识别功能需求（用户明确提出的功能）
    ↓
识别非功能需求（性能/安全/体验等）
    ↓
识别业务规则（流程/约束/逻辑）
    ↓
识别数据需求（存储/处理/流转）
    ↓
识别接口需求（集成/对接）
    ↓
结构化需求描述（统一格式）
    ↓
需求优先级初步评估
    ↓
输出显性需求清单
    ↓
更新状态文件
```

## 详细规范

### 1. 功能需求提取

**提取维度**：

| 维度 | 说明 | 示例 |
|------|------|------|
| **核心功能** | 产品必须实现的基础功能 | 用户注册、任务创建 |
| **增值功能** | 提升用户体验的附加功能 | 数据导出、主题切换 |
| **管理功能** | 后台管理相关功能 | 用户管理、数据统计 |

**功能需求描述模板**：
```json
{
  "functionalRequirements": [
    {
      "reqId": "FR001",
      "category": "core|value-added|management",
      "name": "功能名称",
      "description": "功能描述",
      "source": "原始需求引用",
      "acceptanceCriteria": ["验收标准1", "验收标准2"],
      "priority": "P0|P1|P2",
      "dependencies": ["依赖需求ID"],
      "status": "identified"
    }
  ]
}
```

### 2. 非功能需求提取

**非功能需求分类**：

| 类别 | 子类别 | 说明 | 示例 |
|------|--------|------|------|
| **性能** | 响应时间、吞吐量、并发数 | 系统性能指标 | 页面加载<2秒 |
| **可靠性** | 可用性、容错性、恢复性 | 系统稳定性 | 99.9%可用性 |
| **安全性** | 认证、授权、加密、审计 | 安全防护 | JWT认证 |
| **易用性** | 学习成本、操作效率、满意度 | 用户体验 | 3步完成核心操作 |
| **可维护性** | 可读性、可测试性、可扩展性 | 代码质量 | 单元覆盖率>80% |
| **可移植性** | 跨平台、跨浏览器 | 适配能力 | 支持iOS/Android |

**非功能需求描述模板**：
```json
{
  "nonFunctionalRequirements": [
    {
      "reqId": "NFR001",
      "category": "performance|reliability|security|usability|maintainability|portability",
      "subCategory": "子类别",
      "description": "需求描述",
      "metric": "量化指标",
      "target": "目标值",
      "priority": "P0|P1|P2",
      "source": "原始需求引用"
    }
  ]
}
```

### 3. 业务规则提取

**业务规则类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **约束规则** | 限制条件 | 任务标题不能超过100字 |
| **计算规则** | 计算公式 | 学习时长=结束时间-开始时间 |
| **流程规则** | 业务流程 | 任务创建→分配→执行→完成 |
| **权限规则** | 访问控制 | 仅管理员可删除用户 |
| **验证规则** | 数据校验 | 手机号必须符合11位格式 |

### 4. 数据需求提取

**数据需求维度**：

| 维度 | 说明 | 示例 |
|------|------|------|
| **数据实体** | 核心数据对象 | 用户、任务、日程 |
| **数据属性** | 实体字段 | 用户名、创建时间 |
| **数据关系** | 实体关联 | 用户-任务一对多 |
| **数据量** | 存储规模 | 10万用户，人均100条任务 |
| **数据流转** | 数据流向 | 创建→存储→查询→更新→删除 |

### 5. 接口需求提取

**接口类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **用户接口** | UI/UX相关 | 响应式设计、深色模式 |
| **系统接口** | 内部系统交互 | 与认证服务对接 |
| **外部接口** | 第三方集成 | 微信登录、支付接口 |
| **硬件接口** | 硬件设备交互 | 蓝牙连接、摄像头调用 |

## 错误处理

### 前置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 边界界定报告不存在 | E001 | 返回错误，要求先执行Skill1 |
| 原始需求缺失 | E002 | 返回错误，要求补充需求 |

### 执行过程错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 需求识别冲突 | E101 | 标记冲突，继续执行 |
| 需求分类模糊 | E102 | 标记为待确认 |
| 文件写入失败 | E103 | 重试3次 |
