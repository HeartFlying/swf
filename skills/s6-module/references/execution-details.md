# S6-A01 模块详细设计 - 详细执行步骤说明

本文件包含 S6-A01 模块详细设计 Skill 的详细执行步骤。

---

## 步骤 1：读取前置产物

**目标**：获取模块详细设计所需的全部输入信息

**操作**：
1. 读取架构视图设计文档：`artifacts/stages/s5/{PlanID}/{PlanID}-S5-A02-001.md`
2. 读取数据架构设计文档：`artifacts/stages/s5/{PlanID}/{PlanID}-S5-A03-001.md`
3. 读取接口架构设计文档：`artifacts/stages/s5/{PlanID}/{PlanID}-S5-A04-001.md`
4. 读取需求规格说明书（SRS）
5. 读取非功能需求文档
6. 解析并缓存关键信息：模块划分、数据实体、API定义、业务用例

**验证规则**：
- 所有前置产物文件必须存在
- 产物状态必须为 completed
- 产物ID必须匹配当前PlanID
- 模块划分信息必须完整（至少包含模块名称和职责）

**错误处理**：
- E101：前置产物不存在 → 提示用户先执行前置Skill S5-A06
- E102：产物状态非completed → 提示等待前置Skill完成
- E103：产物ID不匹配 → 返回数据一致性错误

---

## 步骤 2：分析模块特征

**目标**：基于架构视图分析每个模块的特征，为后续设计提供依据

**操作**：
1. 遍历架构视图中的模块划分
2. 对每个模块进行特征分析：
   - 识别模块类型（业务逻辑/数据访问/工具类/控制类）
   - 评估复杂度等级（简单/中等/复杂/极复杂）
   - 分析依赖关系（依赖模块、被依赖模块）
   - 识别设计模式适用性
   - 识别需要特殊设计的核心算法
3. 生成模块特征分析报告

**验证规则**：
- 所有模块都有明确的类型标识
- 复杂度评估有依据（基于类数量预估、方法数量预估）
- 依赖关系无循环依赖

**错误处理**：
- E151：模块类型无法识别 → 标记为待确认，使用默认类型"业务逻辑"
- E152：发现循环依赖 → 标记为风险，提示人工检查架构设计

---

## 步骤 3：设计类结构

**目标**：基于模块特征和数据模型设计完整的类结构

**操作**：
1. 基于领域模型实体识别实体类：
   - 每个领域实体 → 一个实体类
   - 定义类名（名词，大驼峰命名）
   - 定义职责描述（单句描述）
2. 基于API定义识别控制器类：
   - 每个API资源 → 一个控制器类
   - 映射API端点到方法
3. 基于业务用例识别服务类：
   - 每个业务用例 → 一个服务类
   - 定义业务逻辑处理方法
4. 基于聚合根识别仓储类：
   - 每个聚合根 → 一个仓储类
   - 定义数据访问方法
5. 基于接口定义识别DTO类：
   - 每个接口请求/响应 → DTO类
6. 设计类关系：
   - 关联、聚合、组合、继承、实现、依赖
   - 使用Mermaid类图表示

**验证规则**：
- 每个类都有明确的职责描述
- 类命名符合规范（大驼峰命名法）
- 类关系合理，无循环依赖
- 实体类与数据模型一一对应

**错误处理**：
- E153：类职责不明确 → 提示补充需求信息
- E154：类命名冲突 → 自动添加模块前缀区分

---

## 步骤 4：设计方法签名

**目标**：为每个类设计清晰、规范的方法签名

**操作**：
1. 为每个类设计公共方法：
   - 方法命名遵循规范（动词开头，小驼峰）
   - 创建方法：create + 对象名
   - 查询方法：get/find/query + 对象名
   - 更新方法：update/modify + 对象名
   - 删除方法：delete/remove + 对象名
   - 业务操作方法：动词 + 对象
2. 定义方法签名要素：
   - 可见性（public/protected/private）
   - 参数列表（名称、类型、必填/可选、默认值）
   - 返回值类型
   - 异常声明
3. 设计参数验证规则：
   - 必填验证、类型验证、长度验证
   - 格式验证、范围验证、业务验证

**验证规则**：
- 方法命名符合规范
- 参数命名清晰（小驼峰）
- 每个方法都有明确的返回值类型
- 异常声明覆盖所有错误场景

**错误处理**：
- E155：方法命名不规范 → 自动修正为规范命名
- E156：参数类型无法确定 → 标记为待确认，使用Object类型占位

---

## 步骤 5：设计核心算法

**目标**：为复杂业务逻辑设计核心算法

**操作**：
1. 识别需要详细设计的算法场景：
   - 数据排序/筛选 → 排序算法
   - 路径查找 → 图算法
   - 数据匹配 → 匹配算法
   - 权限校验 → 规则引擎
   - 价格计算 → 计算策略
   - 状态流转 → 状态机
2. 为每个算法设计文档：
   - 算法名称和功能描述
   - 输入参数及约束
   - 输出返回值及含义
   - 处理步骤（伪代码或流程图）
   - 边界条件处理
   - 时间复杂度分析（O表示法）
   - 空间复杂度分析
3. 设计状态机（如适用）：
   - 定义所有状态
   - 定义状态转移条件
   - 使用状态表或状态图表示

**验证规则**：
- 算法设计覆盖所有识别到的复杂逻辑
- 时间/空间复杂度分析完整
- 边界条件处理明确

**错误处理**：
- E157：算法复杂度过高 → 提供简化方案供选择
- E158：状态机状态定义不完整 → 标记为待确认

---

## 步骤 6：设计业务流程

**目标**：设计清晰的业务流程和对象交互时序

**操作**：
1. 设计业务流程图：
   - 使用Mermaid flowchart语法
   - 包含开始、结束、判断、处理节点
   - 标注分支条件和处理逻辑
2. 设计时序图：
   - 使用Mermaid sequenceDiagram语法
   - 标识参与交互的对象/类
   - 标注方法调用和返回
   - 展示业务处理流程
3. 为关键业务流程补充文字说明

**验证规则**：
- 流程图语法正确，可渲染
- 时序图覆盖主要业务场景
- 流程与模块详细设计一致

**错误处理**：
- E159：流程图语法错误 → 自动修正或标记为风险
- E160：业务流程与需求不符 → 提示检查需求理解

---

## 步骤 7：应用设计模式

**目标**：基于模块特征应用合适的设计模式

**操作**：
1. 分析模块特征，推荐适用的设计模式：
   - 单例模式：全局唯一实例场景
   - 工厂模式：对象创建复杂场景
   - 策略模式：算法可替换场景
   - 观察者模式：事件通知场景
   - 装饰器模式：动态增强功能场景
   - 代理模式：访问控制场景
   - 模板方法模式：流程固定步骤可变场景
   - 建造者模式：复杂对象构建场景
2. 为每个应用的模式提供：
   - 适用场景说明
   - 实现方式描述
   - 类图或代码结构示意

**验证规则**：
- 设计模式应用有明确场景
- 模式实现方式描述清晰
- 不过度设计（避免模式滥用）

**错误处理**：
- E161：设计模式选择存在争议 → 标记为决策点，等待用户确认

---

## 步骤 8：识别用户确认决策点

**目标**：识别需要用户确认的关键设计决策

**操作**：
1. 扫描设计过程中的决策点：
   - 设计模式选择（多个适用模式时）
   - 算法复杂度权衡（时间vs空间）
   - 依赖注入方式（构造函数vs属性注入）
   - 异常处理策略（检查异常vs非检查异常）
2. 为每个决策点准备选项说明：
   - 各选项优缺点
   - 推荐选项及理由
   - 默认选项（用于超时场景）

**验证规则**：
- 所有关键决策都有明确选项
- 每个选项都有优缺点说明
- 有明确的推荐选项

**错误处理**：
- 无特殊错误处理，本步骤为准备阶段

---

## 步骤 9：用户交互确认

**目标**：就关键设计决策与用户确认

**操作**：
1. 展示设计模式选择（如适用）：
   - 列出可选模式及优缺点
   - 提供推荐选项
   - 请求用户选择
2. 展示算法复杂度确认（如适用）：
   - 列出可选方案及复杂度分析
   - 基于数据规模给出推荐
   - 请求用户确认
3. 展示关键设计决策确认：
   - 列出所有关键决策
   - 说明决策理由
   - 请求用户确认或修改
4. 记录用户交互结果

**验证规则**：
- 用户交互记录完整保存
- 所有决策点都有明确结果
- 超时使用默认选项并记录

**错误处理**：
- E301：用户交互超时 → 使用默认选项，记录假设
- E302：用户拒绝选择 → 标记为风险，使用推荐选项

---

## 步骤 10：生成设计文档

**目标**：基于自动设计和用户确认生成完整模块详细设计文档

**操作**：
1. 生成模块概述：
   - 模块职责描述
   - 模块划分说明
2. 生成类设计章节：
   - 类图（Mermaid）
   - 类清单表格
   - 类关系说明
3. 生成方法设计章节：
   - 方法签名清单
   - 参数验证规则
   - 异常定义
4. 生成算法设计章节：
   - 核心算法伪代码
   - 复杂度分析
5. 生成流程设计章节：
   - 业务流程图
   - 时序图
6. 生成设计模式应用章节
7. 生成依赖关系章节：
   - 模块依赖图
   - 外部依赖清单

**验证规则**：
- 文档结构完整，包含所有章节
- 所有Mermaid图表语法正确
- 表格格式规范

**错误处理**：
- E201：文档生成失败 → 重试生成，最多3次
- E202：文档格式错误 → 修正格式后重新生成

---

## 步骤 11：质量检查

**目标**：自动检查设计质量，确保符合设计原则

**操作**：
1. 执行设计原则检查：
   - 单一职责：每个类职责单一
   - 开闭原则：优先使用多态而非条件判断
   - 依赖倒置：依赖接口/抽象类
   - 接口隔离：接口方法数 <= 5
   - 迪米特法则：方法链调用深度 <= 3
   - 代码复用：公共逻辑抽取为工具方法
2. 生成质量检查报告：
   - 检查项通过情况
   - 发现的问题及建议
   - 质量评分

**验证规则**：
- 所有检查项都有明确结果
- 严重问题必须修复
- 质量评分 >= 85%

**错误处理**：
- E203：质量检查不通过 → 根据问题清单自动修复
- E204：存在无法自动修复的问题 → 标记为风险

---

## 步骤 12：更新 Todo-List

**目标**：更新任务状态，记录执行结果

**操作**：
1. 更新S6-A01任务状态：执行中 → 已完成
2. 更新评审状态：待评审
3. 记录产物信息：
   - 产物ID：{PlanID}-S6-A01-001
   - 产物路径
   - 生成时间
4. 更新后置任务S6-A02状态：待执行 → 就绪

**验证规则**：
- Todo-List文件更新成功
- 状态变更正确
- 产物信息记录完整

**错误处理**：
- E205：Todo-List更新失败 → 重试更新，最多3次

---

## 步骤 13：用户评审

**目标**：提交设计结果供用户评审

**操作**：
1. 展示设计成果摘要：
   - 模块数量和类数量统计
   - 方法数量统计
   - 核心算法数量
   - 设计模式应用情况
2. 展示核心设计决策
3. 请求用户评审决策：
   - 确认：进入S6-A02
   - 修改：说明具体修改需求
   - 新增：提出新的设计想法
   - 跳过：直接进入下一阶段
4. 根据评审结果处理：
   - 确认：更新状态，进入下一Skill
   - 修改：根据意见修改产物
   - 新增：补充设计需求，重新执行

**验证规则**：
- 评审记录完整保存
- 用户决策明确记录
- 修改需求清晰可执行

**错误处理**：
- E303：用户评审超时 → 标记为已确认，记录风险
- E304：修改需求不明确 → 请求用户澄清
