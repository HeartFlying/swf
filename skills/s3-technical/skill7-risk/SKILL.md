# Skill7: 需求风险识别

## 基本信息

| 项目 | 内容 |
|-----|------|
| **Skill编号** | S3-S07 |
| **Skill名称** | 需求风险识别 |
| **所属阶段** | S3 - 技术可行性与选型阶段 |
| **执行顺序** | 第1个执行（S3阶段入口） |
| **执行模式** | 常规模式执行，轻量化模式可选执行 |
| **执行Agent** | Executor Agent |

---

## 功能描述

### 核心职责

Skill7负责识别和评估需求实现过程中的各类风险，包括：
1. **技术风险识别**：评估技术实现难度、技术栈成熟度等风险
2. **需求风险识别**：评估需求模糊性、变更可能性等风险
3. **资源风险识别**：评估人力、时间、预算等资源约束风险
4. **外部风险识别**：评估政策、市场、竞品等外部因素风险
5. **风险等级评估**：对识别出的风险进行等级划分

### 输入输出

**输入**：
- 前置Skill产物：S2阶段汇总产物（P000001-S2-S10-001）
- 包含内容：市场价值校验清单、竞品分析结果、需求原始表

**输出**：
- 需求风险清单（Markdown表格形式）
- 风险等级评估报告
- 风险应对建议

---

## 执行流程

```
读取S2阶段汇总产物
    ↓
分析需求内容，识别潜在风险点
    ↓
按风险类型分类整理
    ↓
评估每个风险的发生概率和影响程度
    ↓
确定风险等级（高/中/低）
    ↓
制定风险应对建议
    ↓
输出需求风险清单
    ↓
返回执行结果给Coordinator
```

## 详细规范

### 1. 风险类型定义

**固定枚举值**：

| 风险类型 | 代码 | 说明 |
|---------|------|------|
| 技术风险 | TECH | 技术实现难度、技术栈成熟度、技术债务等 |
| 需求风险 | REQ | 需求模糊性、需求变更、需求冲突等 |
| 资源风险 | RES | 人力不足、时间紧张、预算超支等 |
| 外部风险 | EXT | 政策变化、市场波动、竞品动态等 |
| 合规风险 | COM | 法律法规、行业标准、安全合规等 |

### 2. 风险等级定义

**固定枚举值**：

| 风险等级 | 代码 | 判定标准 | 处理优先级 |
|---------|------|----------|-----------|
| 高 | HIGH | 发生概率≥70% 或 影响程度≥严重 | P0 - 必须立即处理 |
| 中 | MEDIUM | 发生概率30%-70% 或 影响程度=中等 | P1 - 需要关注处理 |
| 低 | LOW | 发生概率<30% 且 影响程度≤轻微 | P2 - 常规监控 |

### 3. 发生概率评估

| 概率等级 | 数值范围 | 说明 |
|---------|---------|------|
| 极高 | 90%-100% | 几乎必然发生 |
| 高 | 70%-89% | 很可能发生 |
| 中 | 30%-69% | 可能发生 |
| 低 | 10%-29% | 不太可能发生 |
| 极低 | 0%-9% | 几乎不可能发生 |

### 4. 影响程度评估

| 影响等级 | 说明 | 示例 |
|---------|------|------|
| 灾难性 | 导致项目失败或重大损失 | 核心技术无法实现 |
| 严重 | 显著影响项目进度或质量 | 关键功能延期3个月以上 |
| 中等 | 对项目有一定影响 | 部分功能需要调整方案 |
| 轻微 | 影响较小，易于解决 | UI细节需要优化 |
| 可忽略 | 几乎无影响 | 文档格式调整 |

### 5. 风险识别维度

**技术风险检查清单**：
- [ ] 是否使用了未经验证的新技术？
- [ ] 技术栈是否成熟稳定？
- [ ] 团队是否具备相关技术能力？
- [ ] 是否存在性能瓶颈风险？
- [ ] 是否存在安全漏洞风险？
- [ ] 第三方依赖是否稳定可靠？

**需求风险检查清单**：
- [ ] 需求描述是否清晰明确？
- [ ] 是否存在需求冲突或矛盾？
- [ ] 需求变更频率是否可能较高？
- [ ] 隐性需求是否充分挖掘？
- [ ] 用户期望是否过于理想化？

**资源风险检查清单**：
- [ ] 团队规模是否充足？
- [ ] 交付时间是否合理？
- [ ] 预算是否充分考虑风险储备？
- [ ] 关键岗位人员是否稳定？

**外部风险检查清单**：
- [ ] 相关政策法规是否稳定？
- [ ] 市场竞争态势是否明确？
- [ ] 供应链/合作方是否稳定？
- [ ] 经济环境是否可能影响项目？

## 输出产物

### 产物1: 需求风险清单

**文件路径**：`database/stages/s3/{PlanID}-S3-S07-001.md`

**内容结构**：参见 [template.md](template.md)

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| 风险ID | 字符串 | 是 | 格式：R{3位数字}，如R001 |
| 风险类型 | 枚举 | 是 | TECH/REQ/RES/EXT/COM |
| 风险描述 | 文本 | 是 | 具体风险内容描述 |
| 发生概率 | 枚举 | 是 | 极高/高/中/低/极低 |
| 影响程度 | 枚举 | 是 | 灾难性/严重/中等/轻微/可忽略 |
| 风险等级 | 枚举 | 是 | HIGH/MEDIUM/LOW |
| 应对建议 | 文本 | 是 | 针对该风险的具体应对措施 |
| 负责人 | 文本 | 否 | 建议的风险负责人角色 |

## 错误处理

### 前置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 前置产物不存在 | E301 | 返回错误，要求先完成S2阶段 |
| 前置产物格式错误 | E302 | 返回错误，要求重新生成S2产物 |

### 执行过程错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 风险识别不完整 | E701 | 补充识别遗漏的风险点 |
| 风险等级评估错误 | E702 | 重新评估风险等级 |

### 后置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 风险清单为空 | E703 | 返回警告，确认是否确实无风险 |
| 必填字段缺失 | E704 | 补充缺失字段 |
| 枚举值错误 | E705 | 修正为正确的枚举值 |

## 协作接口

### 与Coordinator Agent的协作

**调用方式**：Coordinator通过Executor Agent调用Skill7

**输入参数**：
```json
{
  "action": "execute_skill",
  "skillId": "S07",
  "input": {
    "previousArtifact": "P000001-S2-S10-001",
    "artifactPath": "database/stages/s2/P000001-S2-S10-001.md"
  }

```

**输出结果**：
```json

  "status": "success|failed",

  "outputs": [
    {
      "artifactId": "P000001-S3-S07-001",

  "riskSummary": {
    "total": 8,
```

### 与Validator Agent的协作

**前置校验**：
- 检查前置产物是否存在且格式正确
- 检查前置产物内容完整性

**后置校验**：
- 检查风险清单格式是否符合模板
- 检查枚举值是否正确
- 检查必填字段是否完整

### 与UserInteraction Agent的协作

**交互场景**：
- 当发现高风险项时，可能需要与用户确认风险描述准确性
- 当风险等级评估存在争议时，可能需要用户参与评估

## 执行示例

### 示例：识别技术风险

**输入场景**：
- 项目要求使用最新的AI大模型技术
- 团队之前没有相关经验
- 交付时间紧张（3个月）

**识别结果**：
| 风险ID | 风险类型 | 风险描述 | 发生概率 | 影响程度 | 风险等级 | 应对建议 |
|-------|---------|---------|---------|---------|---------|---------|
| R001 | TECH | 团队缺乏AI大模型开发经验，技术学习成本高 | 高 | 严重 | HIGH | 提前安排技术培训，考虑引入外部专家支持 |
| R002 | RES | 3个月交付时间紧张，可能无法完成全部功能 | 中 | 严重 | HIGH | 采用MVP策略，优先交付核心功能 |
