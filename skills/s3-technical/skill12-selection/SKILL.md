# Skill12: 轻量化技术选型

## 基本信息

| 项目 | 内容 |
|-----|------|
| **Skill编号** | S3-S12 |
| **Skill名称** | 轻量化技术选型 |
| **所属阶段** | S3 - 技术可行性与选型阶段 |
| **执行顺序** | 第3个执行（S3阶段出口） |
| **执行模式** | 仅常规模式执行，轻量化模式跳过 |
| **执行Agent** | Executor Agent |

---

## 功能描述

### 核心职责

Skill12负责基于技术可行性评估结果，进行技术方案选型和成本评估，包括：
1. **技术方案对比**：对比多个可选技术方案的优劣
2. **技术选型决策**：推荐最优技术方案
3. **实施成本评估**：评估人力、时间、资金成本
4. **实施周期规划**：制定技术实施时间计划
5. **技术选型报告**：输出完整的技术选型及成本表

### 输入输出

**输入**：
- 前置Skill产物：
  - Skill7风险清单（P000001-S3-S07-001）
  - Skill11技术可行性评估表（P000001-S3-S11-001）
- 包含内容：风险清单、技术点评估、可行性结论

**输出**：
- 技术选型及成本表（Markdown表格形式）
- 技术方案推荐
- 实施周期和成本估算

---

## 执行流程

```
读取Skill7和Skill11产物
    ↓
识别需要选型的技术点
    ↓
对比可选技术方案
    ↓
评估各方案的实施成本
    ↓
推荐最优技术方案
    ↓
制定实施周期计划
    ↓
输出技术选型及成本表
    ↓
返回执行结果给Coordinator
```

## 详细规范

### 1. 技术方案对比维度

**评估维度**：

| 维度 | 权重 | 说明 |
|-----|------|------|
| 技术成熟度 | 20% | 技术栈的稳定性和社区支持 |
| 团队熟悉度 | 20% | 团队对该技术的掌握程度 |
| 开发效率 | 20% | 开发速度和维护成本 |
| 性能表现 | 15% | 运行性能和扩展能力 |
| 生态完善度 | 15% | 第三方库和工具支持 |
| 成本控制 | 10% | 许可成本和运维成本 |

### 2. 实施周期格式规范

**时间单位**：人天（PD）

**格式示例**：
- 简单功能：`5 PD`
- 范围估算：`10-15 PD`
- 含缓冲：`20 PD（含20%缓冲）`

### 3. 成本估算格式规范

**成本类型**：

| 成本类型 | 单位 | 说明 |
|---------|------|------|
| 人力成本 | 元/人天 | 开发人员日均成本 |
| 第三方服务 | 元/月 | SaaS服务、API调用等 |
| 基础设施 | 元/月 | 服务器、数据库等 |
| 许可费用 | 元/年 | 商业软件许可 |

**格式示例**：
- 人力：`50,000元（100PD × 500元/PD）`
- 服务：`2,000元/月`
- 总计：`首期60,000元 + 2,000元/月`

### 4. 技术选型决策规则

**决策矩阵**：

| 场景 | 推荐策略 | 说明 |
|-----|---------|------|
| 团队熟悉 + 成熟技术 | 优先选用 | 风险最低，效率最高 |
| 团队陌生 + 成熟技术 | 培训后选用 | 需要投入学习成本 |
| 团队熟悉 + 新兴技术 | 谨慎选用 | 评估技术稳定性 |
| 团队陌生 + 新兴技术 | 避免选用 | 风险过高，除非必要 |

**决策优先级**：
1. 满足核心需求
2. 团队技术栈匹配
3. 成本控制合理
4. 长期可维护性

### 5. 技术选型检查清单

**方案评估**：
- [ ] 是否满足功能需求？
- [ ] 性能指标是否达标？
- [ ] 安全性是否满足要求？
- [ ] 可扩展性是否良好？
- [ ] 社区支持是否活跃？

**成本评估**：
- [ ] 开发成本是否在预算内？
- [ ] 运维成本是否可接受？
- [ ] 第三方费用是否明确？
- [ ] 是否有隐藏成本？

**风险评估**：
- [ ] 技术风险是否可控？
- [ ] 供应商锁定风险？
- [ ] 技术过时风险？
- [ ] 人员流动风险？

## 错误处理

### 前置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 前置产物不存在 | E301 | 返回错误，要求先完成Skill7和Skill11 |
| 前置产物格式错误 | E302 | 返回错误，要求重新生成前置产物 |

### 执行过程错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 技术点识别不完整 | E1201 | 补充识别遗漏的技术点 |
| 方案对比不充分 | E1202 | 补充更多候选方案 |
| 成本估算不合理 | E1203 | 重新评估成本 |

### 后置校验错误

| 错误类型 | 错误码 | 处理策略 |
|----------|--------|----------|
| 选型表为空 | E1204 | 返回警告，确认是否确实无需选型 |
| 必填字段缺失 | E1205 | 补充缺失字段 |
| 成本格式错误 | E1206 | 修正为正确的成本格式 |

## 执行示例

### 示例：数据库技术选型

**技术点**：用户数据存储方案

**候选方案对比**：

| 方案 | 成熟度 | 团队熟悉度 | 开发效率 | 性能 | 生态 | 成本 | 综合得分 |
|-----|-------|-----------|---------|------|------|------|---------|
| MySQL | 高 | 高 | 高 | 中 | 高 | 低 | 85 |
| PostgreSQL | 高 | 中 | 高 | 高 | 高 | 低 | 88 |
| MongoDB | 中 | 低 | 中 | 高 | 中 | 中 | 65 |

**推荐方案**：PostgreSQL

**选型理由**：
- 支持复杂查询和JSON数据类型
- 开源免费，无许可成本
- 性能和扩展性优于MySQL
- 团队有一定使用经验

**成本估算**：
- 实施周期：5 PD
- 人力成本：2,500元
- 基础设施：500元/月
