# Prompt: 显性需求提取 (Skill2)

## 触发条件

当需要执行 Skill2 - 显性需求提取时使用。

## 提示词

```
请执行【Skill2 - 显性需求提取】分析。

## 输入信息
- Plan ID: {PlanID}
- 边界界定报告: artifacts/{PlanID}/01-boundary.md
- 用户原始需求: {需求摘要}

## 执行步骤

1. 读取边界界定报告，理解产品边界
2. 从用户原始需求中提取以下5类需求：

   **功能需求**：
   - 核心功能（P0）：产品必须实现的基础功能
   - 增值功能（P1）：提升用户体验的附加功能
   - 管理功能（P2）：后台管理相关功能

   **非功能需求**：
   - 性能、可靠性、安全性、易用性、可维护性、可移植性

   **业务规则**：
   - 约束规则、计算规则、流程规则、权限规则、验证规则

   **数据需求**：
   - 数据实体、属性、关系、数据量、数据流转

   **接口需求**：
   - 用户接口、系统接口、外部接口、硬件接口

3. 为每个需求分配唯一ID和优先级（P0/P1/P2）
4. 识别需求缺口

## 输出要求

生成产物文件：artifacts/{PlanID}/02-explicit.md

使用模板：templates/all-templates.md 中的 Skill2 模板

需求ID格式：
- 功能需求：FR001, FR002...
- 非功能需求：NFR001, NFR002...
- 业务规则：BR001, BR002...
- 数据需求：DE001, DE002...
- 接口需求：IR001, IR002...

## 特别说明

- 需求描述使用"用户故事"格式：作为[角色]，我希望[功能]，以便[价值]
- 验收标准必须可测试、可衡量
- 非功能需求尽可能量化
```

## 使用示例

```
/swf skill2 P000001
```

或

```
执行显性需求提取，Plan ID: P000001
```

## 预期输出

产物文件 `artifacts/{PlanID}/02-explicit.md`，包含：
- 5类需求清单（功能、非功能、业务规则、数据、接口）
- 需求统计表
- 需求缺口分析
- 用户交互记录
- 评审记录

## 后置操作

1. 更新 `artifacts/{PlanID}/00-todo-list.md`
2. 根据执行模式决定下一步：
   - 常规模式 → 执行 Skill3
   - 轻量化模式 → 跳过 Skill3，执行 Skill4
