# Prompt: 核心需求提炼 (Skill8)

## 触发条件

当需要执行 Skill8 - 核心需求提炼时使用（S4阶段关键节点）。

## 提示词

```
请执行【Skill8 - 核心需求提炼】。

## 输入信息
- Plan ID: {PlanID}
- 优先级排序报告: artifacts/{PlanID}/06-priority.md
- 所有已验证需求: {需求列表}

## 执行步骤

1. **需求梳理**
   - 回顾所有P0级需求
   - 分析需求间的关联关系
   - 识别核心用户价值

2. **核心需求提炼**
   从P0需求中提炼1-3个核心需求：
   - 每个核心需求支撑多个原始需求
   - 体现产品核心价值主张
   - 可量化成功指标

3. **MVP功能确定**
   - 确定必须有（Must have）的功能
   - 明确V1.0及后续版本功能
   - 制定版本规划

4. **需求追溯**
   - 建立核心需求与原始需求的追溯关系
   - 关联技术选型和风险

5. **关键成功因素**
   - 识别产品成功的关键因素
   - 提示主要风险

## 输出要求

生成产物文件：artifacts/{PlanID}/08-core.md

使用模板：templates/all-templates.md 中的 Skill8 模板

核心需求格式：
| 项目 | 内容 |
|------|------|
| 需求ID | C001 |
| 需求描述 | {描述} |
| 支撑原始需求 | {需求ID列表} |
| 核心价值 | {价值说明} |
| 成功指标 | {可量化指标} |
| 优先级 | P0 |
| 建议实现阶段 | MVP |

## 特别说明

- 核心需求数量控制在1-3个
- 必须有明确的成功指标
- 体现产品的差异化价值
- 这是最终产物，必须评审
```

## 使用示例

```
/swf skill8 P000001
```

或

```
执行核心需求提炼，Plan ID: P000001
```

## 预期输出

产物文件 `artifacts/{PlanID}/08-core.md`，包含：
- 1-3个核心需求详细描述
- 需求追溯矩阵
- MVP功能清单
- 后续版本规划
- 关键成功因素
- 风险提示

## 后置操作

1. 更新 `artifacts/{PlanID}/00-todo-list.md`
2. **必须触发用户评审**（关键节点）
3. 根据用户选择决定是否执行 Skill15（原型设计）
4. 生成最终报告

## 评审要点

用户评审时需确认：
- [ ] 核心需求是否准确反映产品价值
- [ ] MVP范围是否合理
- [ ] 成功指标是否可衡量
- [ ] 版本规划是否可行
