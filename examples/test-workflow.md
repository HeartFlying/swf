## 一、测试概述

### 1.1 测试目标

验证 Agent+Skill 用户需求分析系统的完整功能，确保：
1. **流程连通性**：所有 Agent 和 Skill 能正常协作
2. **模式切换**：常规模式和轻量化模式能正确触发
3. **断点续跑**：支持任务中断和恢复执行
4. **异常处理**：能正确处理各种异常情况
5. **产物质量**：输出产物符合标准化规范

### 1.2 测试范围

| 测试类型 | 测试内容 | 优先级 |
|---------|---------|--------|
| 首次执行测试 | 完整执行流程验证 | P0 |
| 常规模式测试 | 模糊需求触发常规模式 | P0 |
| 轻量化模式测试 | 完整需求触发轻量化模式 | P0 |
| 断点续跑测试 | 中断后恢复执行 | P0 |
| 异常处理测试 | 校验失败/依赖缺失等异常 | P1 |
| 用户交互测试 | 3 个交互节点触发 | P1 |

### 1.3 测试环境要求

**前置条件**：
- [ ] 所有 Agent 文件已创建（coordinator.md, validator.md, user-interaction.md, executor.md）
- [ ] 所有 Skill 定义已创建（13 个 Skill 的 SKILL.md 和 template.md）
- [ ] WORKFLOW.md 已创建
- [ ] database/目录结构已初始化
- [ ] Plan-Status.json 和 Plan-Resume.json 已创建

**测试工具**：
- Trae IDE 或支持 Agent 执行的环境
- 文件浏览器（查看产物文件）
- JSON 查看器（查看状态文件）

## 四、测试用例 3：断点续跑测试

### 4.1 测试目标

验证系统在任务中断后，能正确保存断点并从断点位置恢复执行。

### 4.2 测试场景

**场景**：在 S1 阶段 Skill2 执行完成后，手动暂停系统，然后恢复执行。

### 4.3 测试步骤

#### 步骤 1：启动常规模式执行

1. 输入模糊需求（示例需求 1）
2. 开始执行

#### 步骤 2：制造中断

**中断时机**：等待 S1 阶段 Skill2 执行完成后

**中断操作**：
1. 在 Coordinator Agent 中输入：`暂停` 或 `保存进度`
2. 或者手动停止执行

#### 步骤 3：验证断点保存

**检查 resume.json**：
```json
{
  "planId": "P000001",
  "canResume": true,
  "resumeStatus": "user_paused",
  "breakpoint": {
    "stage": "S1",
    "skill": "S03",
    "action": "execute",
    "interruptedAt": "2026-03-24T10:30:00Z",
    "reason": "用户主动暂停"
  },
  "context": {
    "lastCompletedStage": "S1",
    "lastCompletedSkill": "S02",
    "lastCompletedOutput": "P000001-S1-S02-001"
  }
}
```

**检查 status.json**：
```json
{
  "status": "paused",
  "currentStage": "S1",
  "currentSkill": "S02"
}
```

#### 步骤 4：验证已保存的产物

**检查点**：
- [ ] Skill1 产物存在：`database/stages/s1/{PlanID}-S1-S01-001.md`
- [ ] Skill2 产物存在：`database/stages/s1/{PlanID}-S1-S02-001.md`
- [ ] Skill3 产物不存在（尚未执行）

#### 步骤 5：恢复执行

**恢复操作**：
1. 重新启动 Coordinator Agent
2. 系统自动检测到 resume.json
3. 显示恢复执行提示
4. 确认恢复

#### 步骤 6：验证恢复位置

**检查点**：
- [ ] 系统从 Skill3 开始执行（不是从头开始）
- [ ] 已完成的 Skill1 和 Skill2 不重复执行
- [ ] 执行上下文正确恢复

#### 步骤 7：验证恢复后执行

**检查点**：
- [ ] Skill3 正常执行完成
- [ ] Skill4 正常执行完成
- [ ] 后续阶段正常执行
- [ ] 最终状态为 completed

### 4.4 验收标准

- [ ] 中断后正确保存断点
- [ ] resume.json 信息完整
- [ ] 已执行产物不丢失
- [ ] 恢复后从断点位置继续（非从头开始）
- [ ] 恢复后流程正常完成
- [ ] 最终状态正确更新

## 五、测试用例 4：异常处理测试

### 5.1 测试目标

验证系统在各种异常情况下的处理能力。

### 5.2 测试场景

#### 场景 1：前置校验失败

**触发方式**：
1. 手动修改 Skill2 的输入数据，删除必填字段
2. 触发 Skill2 执行

**预期行为**：
- Validator Agent 检测到字段缺失
- 返回校验失败错误
- 触发重跑机制（最多 3 次）
- 3 次重跑失败后保存断点

**检查点**：
- [ ] 校验错误正确识别
- [ ] 重跑机制触发
- [ ] 错误日志正确记录
- [ ] 断点正确保存

#### 场景 2：后置校验失败

**触发方式**：
1. 手动修改 Skill1 的输出产物，删除元信息字段
2. 触发后置校验

**预期行为**：
- Validator Agent 检测到元信息缺失
- 尝试自动修复（如可修复）
- 若不可修复，触发重跑

**检查点**：
- [ ] 后置校验正确执行
- [ ] 自动修复功能正常（如适用）
- [ ] 重跑机制触发

#### 场景 3：依赖产物缺失

**触发方式**：
1. 删除 Skill1 的产物文件
2. 尝试执行 Skill2

**预期行为**：
- Executor Agent 检测到依赖缺失
- 返回错误给 Coordinator Agent
- Coordinator Agent 触发回溯执行
- 重新执行 Skill1

**检查点**：
- [ ] 依赖检查正确执行
- [ ] 回溯机制触发
- [ ] 缺失产物重新生成

#### 场景 4：用户交互超时

**触发方式**：
1. 触发用户交互（节点 1）
2. 等待超时（300 秒）

**预期行为**：
- UserInteraction Agent 检测到超时
- 返回超时状态给 Coordinator Agent
- Coordinator Agent 决定：
  - 重新发起交互，或
  - 使用默认值继续，或
  - 暂停等待用户

**检查点**：
- [ ] 超时正确检测
- [ ] 超时处理策略正确执行

### 5.3 验收标准

- [ ] 各种异常能正确识别
- [ ] 异常处理策略正确执行
- [ ] 错误日志详细记录
- [ ] 系统不崩溃，能继续执行或安全暂停
