# 示例需求 1：模糊需求（常规模式测试用例）

## 需求描述

我想做一个刷题 APP。

---

## 用途说明

此示例用于测试**常规执行模式**，特点如下：

### 信息完整度评分预估：25-40 分（<90 分，触发常规模式）

**评分分析**：
- **边界清晰度**: 12/25 分
  - 产品目标：模糊（仅知道是刷题 APP）
  - 目标受众：未指定
  - 核心场景：未指定
  
- **需求具体度**: 5/25 分
  - 显性功能：未列出
  - 非功能需求：未提及
  
- **约束明确度**: 3/25 分
  - 时间约束：无
  - 预算约束：无
  - 技术约束：无
  - 资源约束：无
  
- **目标明确度**: 5/25 分
  - 核心价值：模糊
  - 商业目标：未指定
  - 落地指标：无

### 预期执行行为

1. **执行模式**: `normal` (常规模式)
2. **执行 Skill**: 完整执行所有 13 个 Skill
3. **用户交互**: 高频触发（节点 1 信息补全）
   - 需要补充目标受众
   - 需要补充核心场景
   - 需要补充功能需求列表
   - 需要补充约束信息
   
4. **执行时长**: 预计 5-10 分钟
5. **产物输出**: 全量细节版标准化产物

### 测试验证点

- [ ] 信息完整度评分是否正确（应<90 分）
- [ ] 是否正确触发常规模式
- [ ] 是否执行所有 13 个 Skill
- [ ] 是否在节点 1 触发用户交互（信息补全）
- [ ] 产物是否包含所有细节字段
- [ ] 断点续跑功能是否正常

---

## 使用方式

在 Coordinator Agent 中输入此需求文本，系统将：
1. 执行 Skill0 进行信息评分
2. 判定为常规模式（normal）
3. 分阶段执行所有 Skill
4. 在信息缺失时触发用户交互
5. 输出完整的需求分析报告
